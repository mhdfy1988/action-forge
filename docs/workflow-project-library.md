# 工作流工程目录

主入口为`/workflow`，顶部“工程 / 工作流”按需展开目录，左侧继续只负责添加节点。工程组织多张独立画布，不把所有动作塞进一个画布。

## 已实现与边界

- 工程：新建、切换、改名、删除确认；工作流：搜索、新建、切换、改名、复制、删除确认。
- 工程和工作流统一使用每行「⋯」或右键菜单管理，不在目录底部常驻改名/删除。操作绑定点击条目的稳定ID，管理非当前工程不切换当前画布。
- 切换或管理前同步保存当前画布；素材导入中暂不允许切换。清空画布不改名称；删除最后一张画布或最后一个工程后建立空容器，不注入示例节点。
- 复制深拷贝画布清单，共享不可变素材引用。删除仅移除归属与画布清单，暂不回收IndexedDB原文件，避免破坏其他画布。
- 目录和画布是当前浏览器本机草稿，素材在IndexedDB。不是磁盘工程文件，不提供跨设备同步、跨画布连线或引用编排，也不代表抽帧等执行器已接通。

## 保存路径

`web/workflow-library.js`只管理工程归属和当前选择；`web/workflow-navigation.js`负责顶部目录和应用内确认，`web/workflow.js`仍复用原工作流核心、素材库及保存链路。

目录键为`action-forge.workflow-library.v1`，新画布键为`action-forge.workflow.flow.<id>`。第一次打开将原`action-forge.workflow.r6b.v1`作为默认工程第一张画布，不改写原字节、不清数据；目录存在后不再自动从其他缓存迁入。早期独立预览数据不导入正式目录，预览文件与入口已移除。

工作流展示名称以目录为准，加载时映射到现有工作流模型；保存时同步名称。先保存新画布再提交目录，目录保存失败不改变当前选择；失败可能留下未被引用的空草稿，后续统一素材/草稿回收时处理，不静默回退旧路径。

目录或同一画布在其他页面发生修改时，保存显式报错并要求刷新，不覆盖另一页已提交的数据。损坏目录或清单不删除、不自动重建覆盖。当前采用同步浏览器存储检查，不能当作服务端跨进程事务或协同编辑保证。

## 验证

`tests/web/workflow-library.test.mjs`覆盖旧草稿纳入、复制引用、删除隔离、目录损坏、存储失败与目录冲突。

`tests/browser/workflow-navigation.spec.js`在隔离Chrome上下文真实点击主入口，覆盖必填为空时取消/关闭、新建/切换/改名/复制/删除、立即切换保存、刷新恢复、真实PNG复制回读、删除副本保护原图、窄屏目录与同画布多页面冲突。画布交互和原有媒体导入测试继续保留。
