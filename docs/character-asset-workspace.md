# 角色动作资产工作台方向

## 决策

动作工坊不新建第二个产品仓库，也不继续拆出彼此孤立的小工具。现有 `action-forge` 继续作为唯一主项目，但新版产品从空项目和新的工作流协议开始，不以兼容测试阶段页面、缓存或项目数据为前提。

R0至R5验证了项目保存、抽帧、帧处理、抠图、共享画布、事件、Godot预览和JavaScript适配等技术能力，但这些是组件与测试基线，不代表已经形成完整产品，也不存在需要为其迁移的正式用户历史数据。新版可以通过适配层复用经过验证的领域能力，但不能让旧页面结构决定产品形态。

2026-10-10 已进一步确认R6交互结构：不再把“角色总览、单动作制作、跨动作编排”固化成三个割裂页面，而是使用一张可操作工作流画布创建、连接、配置和运行功能节点；资产通过强类型端口流动，复杂编辑从节点进入专注工作区，单帧精修等单点任务使用弹窗。正式实现尚未开始，详见[R6可操作工作流画布计划](stages/character-workspace-r6-canvas-plan.md)和[工作流画布与节点模型](workflow-canvas-node-model.md)。

## 为什么不新起项目

- 现有抽帧、整理、抠图、精修和导出已经共享同一批帧身份、修订和缓存语义，拆仓会重新制造导入导出与状态同步问题。
- 角色资产需要复用现有已验证能力；但当前页面由同一个会话状态串联全部阶段，不适合直接承载多角色、多动作和引擎连接。
- 引擎接入依赖角色、动作名、循环、帧率、共享画布和稳定原点。只做孤立的引擎导入工具会很快因协议不足返工。
- Godot、JavaScript 等目标差异应由适配层处理，不应各自复制动作工坊的核心业务。

因此采用“同仓隔离演进”：核心领域、角色工作区和引擎适配器使用新边界，旧页面保持稳定；只有将来引擎插件需要独立版本、独立发布或被其他工具复用时，才评估拆成独立包或仓库。

## 目标模型

```text
角色资产
├─ 角色基准：参考图、共享画布、稳定原点、默认尺寸
├─ 动作：待机、跑步、跳跃、攻击……
│  ├─ 源视频与抽帧来源
│  ├─ 帧顺序、循环、帧率与事件
│  ├─ 整理、抠图和精修结果
│  └─ 动作级缩放、偏移与旋转
└─ 派生结果：PNG序列、图集、项目中立JSON、引擎适配产物
```

内部关系统一为：`角色资产 → 动作片段 → 动作帧/事件`。单动作旧项目等价于“仅包含一个动作的角色资产”，迁移不得破坏原始帧和已精修结果。

## 工作流

产品不再把制作过程固定成一组必须逐页通过的阶段。用户在同一张工作流画布上组合内置功能节点，资产沿强类型端口流动；复杂编辑从节点进入专注工作区，单帧精修等单点任务使用弹窗。

典型纵向流程是：

```text
角色参考图 → 生成动作视频 ┐
                          ├→ 提取序列帧 → 整理/抠图 → 制作动作片段 ┐
导入动作视频 ────────────┘                                      ├→ 组装角色资产 → 游戏预览/导出
角色参考图 ─────────────────────────────────────────────────────┘
```

整理与抠图允许按素材情况交换先后；画布也可以保留尚未连接的草稿分支。运行目标节点时只检查它需要的上游闭包，复用结果签名仍有效的节点，从相关依赖路径最早的失效节点继续执行。上游改变会使相关下游进入“待更新”，但不会立即重算，也不会影响无关动作分支。

## 动作编排边界

第一版负责：

- 动作名称、分类和顺序；
- 是否循环、动作帧率、逐帧时长；
- 帧顺序、禁用帧和基准帧；
- 角色原点、角色级尺寸和动作级偏移；
- 轻量事件点，例如命中、脚步声或起跳时刻；
- 动作切换和真实尺寸预览。

第一版不负责游戏输入、角色状态机、战斗判定、AI逻辑或复杂动画混合。这些属于游戏引擎；动作工坊只描述可复用的动作资产和事件标记。

## 引擎接入边界

```text
动作工坊角色资产
        ↓
项目中立运行时数据
        ↓
本机预览桥
   ├─ Godot预览适配器
   └─ JavaScript预览适配器
```

- 动作工坊项目数据是唯一编辑真值。
- 引擎产物是可重复生成的派生结果，不能反向成为编辑源。
- 拖动参数时只同步缩放、偏移、原点、帧率等轻量数据；松开或明确应用后再重建图片和图集。
- 每次同步携带单调递增的修订号；引擎忽略迟到的旧修订。
- 正式资产先写临时文件并完整校验，再原子替换，避免引擎读到半份文件。
- 预览桥默认只监听本机；“实时预览”和“写入正式游戏工程”是两个明确操作。
- 核心只依赖项目自己的中立协议，Godot、JavaScript API 由仓库内适配层隔离。

## 仓库与演进组织

不创建新的顶级仓库。R6在当前仓库内建立新的工作流项目协议、节点注册表、资产修订和执行边界；旧 `/` 与 `/projects` 页面只作为R0至R5技术验证入口，在R6纵向流程完成前保持隔离，不作为新版产品信息架构，也不存在正式用户数据迁移要求。

- 工作流核心：项目图、节点定义、强类型端口、连接校验、结果签名、增量执行和修订保存。
- 领域适配层：复用抽帧、整理、抠图、精修、动作编排和导出核心，不复制第二套实现。
- 专注工作区：整理、抠图、动作片段和跨动作校准等复杂编辑器，由所属节点打开。
- 运行时协议：引擎无关的角色资产清单和增量预览消息。
- `integrations/godot-preview/`：Godot只读实时预览工程；正式导入适配器另立后续任务。
- `integrations/javascript/`：JavaScript运行时示例与适配器。

旧实现只能通过命名明确的适配层进入R6；确实只有旧页面持有的逻辑先抽成无界面核心。不得复制业务逻辑，也不得在新路径失败时静默回退到旧页面。

迁移顺序：

1. 当前 `/` 继续作为稳定单动作入口，不增加角色级功能。
2. 新角色工作区使用独立入口，仅接最小角色容器和已有能力适配器。
3. 两个动作、保存恢复、跨动作校准和 Godot 预览全部验收后，才讨论切换默认入口。
4. 默认入口切换后保留一个明确命名的旧工作台入口用于有限迁移期；到期删除，不做永久静默回退。

## 分阶段实施

R0的具体工作包、状态变化和验收门禁见[R0角色工作区准备计划](stages/character-workspace-r0-plan.md)。

### R0 方向与协议基线

- 固化角色资产、动作片段、动作帧和事件的术语。
- 设计可版本迁移的项目中立格式。
- 明确旧单动作会话升级规则和原始素材持有关系。
- 画出现有能力到新版领域接口的依赖图，确认哪些可以直接复用、哪些需要先从页面状态中抽离。
- 确定新版独立入口、状态容器和目录边界，不改当前默认入口。

退出条件：示例JSON、状态变化、不变式和迁移规则通过文档评审，尚不宣称功能可用。

### R1 最小角色资产容器

- 已完成：一个角色可以创建、重命名、排序和切换多个动作，独立保存动作帧率与循环参数。
- 已完成：新版角色工作区使用独立状态和可重启回读的项目仓库，不依赖临时任务缓存作为长期真值。
- 已完成：抽帧v2、整理v3和抠图v4结果通过显式适配器迁入；仅源图输入保持“未抠图”，不伪造透明资产。
- 保留边界：抽帧、整理、抠图和导出的完整角色内编辑整合按后续能力逐步接入，不复制旧页面状态。

退出条件：已通过。`run`与`jump`可独立编辑、保存和重新打开；修改`jump`不增加`run`修订，旧 `/` 回归保持通过。

### R2 跨动作一致性（已完成）

- 已完成：严格协议支持角色基准动作/帧、共享画布原点和动作锚点；几何公式由独立模块覆盖。
- 已完成：校准弹窗支持基准半透明叠图、点选锚点/原点、动作整组缩放/偏移和实时帧播放。
- 已完成：真实PNG双动作项目保存、回读与浏览器刷新恢复；全量旧链路回归通过。
- 尚未包含：自动识别脚底/身体点、逐帧修正和碰撞框。

退出条件：跑步、跳跃等动作在相同真实尺寸画布中切换时，角色尺寸和基准点保持一致。

### R3 Godot实时预览纵向切片

- 定义最小运行时数据和本机预览桥。
- 仓库内提供Godot预览工程和薄适配器。
- 动作切换、播放速度、缩放、偏移、共享画布和原点可以实时刷新。
- 正式资产写入/读取用户工程与临时预览明确分离，作为后续独立阶段规划（R3不执行）。

退出条件：动作工坊调整两个动作时，Godot预览场景无需重启即可看到新修订，且重连可恢复最新快照；正式产物写入/回读用户工程不属于R3，后续另立阶段。当前R3已在Godot 4.7.2 stable与Chrome隔离验收通过，状态见[当前任务](stages/current-todo.md)。

### R4 动作编排与事件

- 已完成R4-A至R4-D：v1只读内存升级、首次保存写入v2；固定帧率/逐帧时长互斥；帧事件按稳定帧ID编辑，禁用关联帧时明确处理；循环预览记录实际触发时间；ZIP包含中立v2清单和引用素材；Godot预览只读验证逐帧时长/事件。详见[R4动作编排与事件](stages/character-workspace-r4-plan.md)。
- R4已完成；用户游戏工程接入、执行事件逻辑仍不属于R4。

### R5 JavaScript动作资产适配器（已完成）

- 已严格读取R4角色ZIP解压后的中立v2清单与相对路径PNG，提供无特定游戏框架依赖的JavaScript运行时适配器和示例宿主。
- 已验证动作切换、播放/循环、固定帧率与逐帧时长、事件触发时序、共享画布/原点/变换、透明像素和资源释放。
- 第一版不写入用户游戏工程，不实现具体游戏状态机或引擎插件；输入无效时显式失败，不静默回退。
- R5详细范围、状态流和退出门禁见[R5 JavaScript动作资产适配器计划](stages/character-workspace-r5-plan.md)。
- 碰撞框、攻击拖尾、附加图层与高级烘焙未并入R5，后续需重新确定下一阶段范围。

## 不变式

- 原视频、源帧、抠图结果和人工精修结果只读保留，不被派生产物覆盖。
- 同一角色所有动作共享坐标基准；单个动作不能独立紧裁后再撑满画布。
- 角色级修改影响全部动作，动作级修改只影响当前动作，单帧覆盖必须显式存在。
- 查看、勾选、编辑状态和正式导出集合保持区分。
- 引擎适配失败必须显式报告，不能静默回退到旧导出逻辑。
- 项目保存、实时预览、正式应用和发布是四种不同状态，不互相推断。
