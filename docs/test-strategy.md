# 测试职责与代码整理

## 保留的分层

- tests/web：参数、时钟、整理、循环与缓存的纯值边界。
- tests/test_*.py：抽帧/来源、资源安全、取消/失败、修订和导出RGBA契约；真实模型门槛须显式开关。
- tests/browser：真实DOM、拖动/勾选/播放、iframe同步、控件状态与几何、实际下载。600帧、慢响应和关闭竞态不是冗余用例，不能用最终HTTP200替代。
- tests/synthetic_matting.py：供测试服务与像素测试复用的确定性形状处理器；不从测试用例模块导入处理器，不接到生产服务。
- scripts/check-chrome-download.py与check-organizer-download.py：重读浏览器原字节兼容输出，对照源PNG/顺序，是独立文件证据，不是生产UI入口。

## 本轮清理

删除未使用导入/局部变量、过时的“顶部导出”测试标题；移除固定写入主8897的旧acceptance-live.py（其功能已有接口/浏览器用例），本机output归档可恢复。旧frameAt按源时长定位帧，仅其自身测试调用，已移除实现和旧断言；实际播放仍用有边界/调速/负时钟回归的FramePlayback。保留有不同风险覆盖的Python和浏览器用例，不为了减少数量删断言。诊断脚本是显式开发工具，不加入主服务导入或用户菜单。

导出纯参数和有界LRU缓存有独立测试；新增13帧循环请求数量验证，核对元数据修改不重算。完整套件与定向测试不得同时共享测试服务；最终验收用新缓存。测试环境8898/FRAMES_TEST_URL和主8897必须区分，结束只停止自己创建的PID。

## 后续优化边界

当前无证据支持重写抽帧/模型/循环算法或引入前端框架；保留模块边界。未来拆更多组件应有具体重复逻辑或生命周期风险，不只按文件行数判断。大图缓存受128MiB预算，不为“所有循环零请求”取消上限。
