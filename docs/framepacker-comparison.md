## 已核对的公开入口

[FramePacker视频转序列帧](https://www.framepacker.cn/pages/video-to-frames/video-to-frames)。本轮通过Chrome只读页面可见内容，不操作页面已有素材、不修改参数、不点击提取。

- 页面按“帧提取 → 编辑与整理 → 导出”分区；我方当前M1只对照帧提取及原尺寸PNG序列下载，整理/图集等留给后续模块。
- 页面明确提示依赖浏览器解码视频，建议电脑端Chrome/Edge/Safari；这是产品提示，不等于已验证其内部实现。我方用本机FFmpeg实际解码，Chrome只承担预览。
- 可见起始/结束时间、采样帧率、预计帧数、开始提取。采样条显示1至60，数值输入的DOM未声明min/max，不能仅据此断言它实际允许超限；不做未经授权的参数实验。
- 可见登录/Pro入口及工程相关Pro提示；没有据此推断PNG导出一定收费，是否受限须在真正对照流程中查看。不登录、不接受新协议、不付费、不绕过限制。

只用本项目自制视频，不使用用户游戏视频、角色立绘或私人文件。该素材只有帧号、颜色块和几何图形。

| 项目 | 固定值 |
| --- | --- |
| 文件 | `output/fixtures/自制 动作测试.mp4` |

| 视频 | 320×180、24fps、2秒、48源帧 |
| 片段 | 0.25至1.25秒，长度1秒 |
| 采样 | 12帧/秒；原尺寸，不调色、不去背景、不去重 |

## 获得外部导入确认后的步骤

1. 导入上表这个确定文件，记录实际显示尺寸/时长；如果需账户或收费，停止并记录限制，不换私人素材。
2. 设置相同片段/采样/原尺寸，核对预计数和实际提取数。若不提供同等参数或原尺寸导出，如实记录不可直接对照，不偷偷改我方参数来凑一致。
3. 检查12张图的帧号、顺序、首末画面；通过其正常界面下载允许导出的结果，不读取隐藏状态或绕过服务。
4. 本地重读竞品文件，核对实际文件数、格式/尺寸、顺序和图像内容。若浏览器与FFmpeg的色彩转换有差异，分开记录错帧与颜色差异，不把所有字节不一致称为提取错误。
5. 将缺功能、操作不便、格式差异、正确性错误分开归类。只在同条件实际证据具备后更新本表和V4；不据此加入M2/M5功能，也不宣传全面胜出。
