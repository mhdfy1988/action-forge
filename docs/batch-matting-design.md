# 序列帧批量抠图与人工精修

> 历史设计/验收记录，保留原日期与证据；其中旧界面、旧策略、端口进程与待开发描述不代表当前状态。当前能力以 [README](../README.md)、[项目计划](project-plan.md) 和 [导出设计](export-design.md) 为准，禁止照历史步骤覆盖用户当前环境。

日期：2026-10-07。状态：B1–B4本机功能链路已验收，真实游戏素材质量仍待用户试用。不恢复旧模型研究，不重写已有抠图算法，不进入动画编排/图集或客户端打包。

## 目标与入口

抽帧 → 帧处理（整理帧、抠图与精修可自由切换）→ 导出。没有“整理结束”状态或按钮。

最新重新抽帧规则：点击提取先清除历史原帧、整理/撤销历史与关联抠图及人工结果，不可撤销，不删除原视频。新提取失败或取消也不恢复旧结果；只切换工具不清理。后端复用缓存安全删除与忙锁，保留其他有效整理会话持有的任务，清理派生批次后清理源帧，禁止只清前端而保留后台持有。

整理结果直接交接图片引用、稳定帧ID、当前顺序和精确时长，不下载再上传。默认输入为整理后保留的全部帧，不是勾选的播放/批量删除集合。删除或排序后的最新序列才是真值。自动抠图只处理像素，不改变顺序、身份、画布尺寸、来源或时长。

## 已确定的界面

用户最新确认：侧栏只有“抽帧 / 帧处理”，处理页内切换“整理帧 / 抠图与精修”。进入帧处理自动建立内部会话，无需做过删除或排序。两视图使用同一有序保留帧列表，按稳定ID关联原图/自动/人工结果；双击帧卡片或大图打开双侧弹窗，移除精修和保存按钮。逐帧历史重开时重新开始，已同步像素保持。

### 实时精修与透明序列预览（R4）

- 输入仍是该帧的不可变原图、自动结果和最新人工RGBA；画笔拖动即时更新局部画布，每笔提交、撤销/重做、重置后200毫秒合并同步，序列化PNG经原修订号PUT接口写回。同步期间锁定编辑，防止旧响应清除新修改；不重跑模型，不影响单图8896手动导出。
- 子页成功后回报修订号，父页更新对应大图和缩略图。关闭发送明确flush请求，只有子页在该请求后确认无脏修改/无任务才销毁iframe，不能用过期状态消息判定成功。失败保留编辑与窗口并提示，再次关闭重试；无无限自动重试或旧实现兜底。浏览器刷新/服务重启不提供工程恢复，仍需导出ZIP。
- 透明播放使用现有FramePlayback和performance.now，默认12、整数1–60帧/秒，按当前全部保留帧顺序循环，调速保持进度。仅全帧抠好后允许播放；未抠帧不混入原图。查看卡片、切换工具、顺序改变、精修、导出或页面隐藏停止播放。播放不改编辑历史、图片字节、来源时间或清单；整理视图只播勾选帧的规则保持。

## 已有实现与复用边界

最新2026-10-07：用户确认模型＋FFmpeg。批量worker先显式调用`GameArtEngine.cutout(..., postprocess=False)`，再在可信均匀亮绿幕应用`app/green_despill.py`局部RGB修正；Alpha、主体内侧核心保持，旧三分图/前景估计/软边网络继续关闭。参数与四帧冻结候选一致，未引入新权重。单图8896默认调用未改、未重启。派生清单`processingPolicy=model-local-despill-v1`，不同策略父批次不能补抠继承。每帧记录despill方法/修改数或跳过原因；单次FFmpeg20秒、两个线程，取消在Windows结束本批拥有的模型/滤镜进程树。重新抠图显式确认，不迁移旧人工结果。

- 自动：同级game-art-matting/app/engine.py的GameArtEngine.cutout，以及其正式边缘/前景颜色处理。默认ToonOut 1024，可信暗绿走HR-matting 2048；模型缺失/运行失败显式报错，不切换模型或色键兜底。原图已有Alpha的路由也沿用现有引擎，不重新定义。
- 人工：game-art-matting/web/src/editor.js、selection-preview.js、worker.js和现有UI适配。支持双侧去除/恢复画笔、大小/硬度/强度、魔法棒原图取色/虚线选区/确认、撤销/重做/重置。PNG直通RGBA为真值，Canvas只作显示。
- 交接：当前app/organizer.py的稳定ID校验与清单派生、Store的源任务持有和下载释放、FrameEditor的当前顺序。先加适配入口，不复制领域核心。
- 只给当前帧精修，不把一帧的笔画或魔法棒选区自动套到其他帧；第一版不做跨帧传播、框选/套索、自动补画或新训练。
- 本工具不引入旧桌面运行时。8896单图工具及其自动质量基线保持；跨仓变更限于明确的复用适配和规划同步。

## 输入、状态与输出

输入快照包括整理会话、源任务、完整有序ID和版本标识。批量启动时固定，后续整理变化不能偷偷改正在处理的队列。服务端从原v2清单和当前顺序派生v4；`derivation`记录父任务/父序列/有序ID/时长规则，`matting`记录模型与人工修改，ZIP中另列`manualFrameIds`。帧ID、源PTS、原帧索引和有理数时长保持；导出文件名按当前顺序连续编号。

1. 首次交接：校验输入/原尺寸/预算并持有源 → 待处理；不修改M1/M2。
2. 点击批量抠图：排队 → 逐帧运行，显示完成数/总数；同一批只运行一个推理任务，不同时加载多套模型。
3. 全部成功且PNG/身份/尺寸校验通过：发布完整透明序列 → 可精修/导出。
4. 失败或取消：明确定位失败帧，保留原素材、之前完整结果和有界中间证据，不把部分输出称作完成；恢复/重试规则在批量协议中固定。
5. 双击打开精修：加载不可变原图、不可变自动结果、当前人工结果 → 编辑当前帧；每次已提交修改自动同步后更新该帧及缩略图。关闭等待同步确认，失败保留窗口和修改供重试。重跑自动结果不能静默覆盖人工修补。

人工编辑历史按当前图一次完整笔画/一次选区确认计步，复用既有有界历史；切帧后重新打开是新历史，已同步PNG保留。正常关闭不再询问保存，但不能关闭丢弃同步失败的修改；不承诺跨刷新或工程恢复。

输出另存透明PNG序列及显式派生清单，保留帧身份、当前顺序、源坐标及有理数时长。原图、自动PNG与人工PNG分别保存，保存有修订号冲突检查。全部成功才发布，失败/取消保留原完整结果。抠图后再删除/交换时，POST下载接口接收当前有序ID并重新派生清单，PNG跟随身份；未抠帧禁止透明导出。撤销/重置恢复未抠帧时，提交`parentBatchId`复用同源已有自动/人工/缩略图及修订号，只推理缺失帧；跨源父批次明确拒绝。新素材不会沿用旧修补。

## 资源与验证

后台任务有界、串行，检查磁盘/像素/时间预算；取消须结束本轮拥有的推理任务，不杀8896或其他用户进程。先核对现有环境/模型/成熟处理路径，再确定独立进程或共享服务适配，不能靠复制代码隔离。

测试用`FRAMES_MATTING_CPU_ONLY=1`固定CPU；生产运行可沿用M0设备选择，GPU是否使用取决于既有模型环境。单批最长45分钟、串行一个子进程，受原RGBA/磁盘/缓存预算约束；取消只终止本批拥有的子进程，不触碰8896。重启清理本工具缓存中的未导出结果，须先导出；不安装/下载新模型、不收费或外传私人素材。

验收包括：直接交接排序/删帧快照、逐帧透明PNG及尺寸/ID/精确时长、队列进度/失败/取消/重试、自动与人工结果分离、双侧坐标/笔刷/魔法棒、保存/撤销/重置、逐帧导出字节一致与内存/磁盘约束。浏览器验证用独立端口/缓存；真实模型检查与模拟API测试分别记录。批量成功不等于时序无闪烁或商业自动质量完美，须播放检查并保留已有质量限制。
