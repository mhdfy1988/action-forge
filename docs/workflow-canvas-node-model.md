## 核心定义

### 画布

画布是可编辑、可执行、可保存的工作流，不是只读流程图或页面导航图。

用户可以在画布上：

- 创建、删除、移动、复制节点；
- 从输出端口拖线到兼容的输入端口；
- 断开连接和建立分支；
- 选择节点并在检查器中修改轻量参数；
- 运行单个节点、选中分支或整张工作流；
- 双击节点进入复杂编辑工作区；
- 查看未连接、待配置、可运行、运行中、已完成、待更新和失败状态；
- 保存节点、连线、参数、画布位置和当前资产修订。

连线交互支持自动吸附：拖动输出线靠近兼容输入端口的32屏幕像素范围内，选择最近的有效端口，端口冰蓝高亮，预览线端点贴合真实中心；松手建立连接，离开范围释放吸附。缩放不改变屏幕操作容差。不兼容、已满、重复或产生依赖环的端口不参与吸附，最终建立仍复用领域核心校验。Escape、指针取消或窗口失焦结束拖动并清理提示，不修改草稿。

### 节点

节点是一个“功能实例”，不是图片、视频、序列帧或动作资产本身。同一种功能可以在一张画布上创建多个实例，例如跑步、跳跃和攻击各自拥有一个“动作视频”节点。

节点至少包含：

- 稳定节点ID与功能类型；
- 独立可编辑的节点名称；
- 强类型输入端口和输出端口；
- 可保存的参数；
- 当前运行状态与错误；
- 输入修订和输出修订；
- 可选的缩略预览；
- 可选的专注工作区入口。

节点名称与类型分开：`WorkflowNode.name`只用于识别，默认“类型名称 + 编号”，可双击卡片上方名称直接修改（1–80字符）。Enter或失焦保存，Escape取消，空白恢复原名。名称前显示类型图标，卡片内部不重复标题、端口数量与版本号；右侧显示当前名称和只读类型。名称不进入业务参数或执行签名，改名不改变类型、连接、素材或结果有效性；不强制跟随上游命名。复制生成独立副本名称，旧草稿缺少名称时按注册表类型补默认名称。

### 节点执行模式

不是所有节点都由动作工坊自动计算。节点定义必须声明一种执行模式：

| 执行模式 | 协议值 | 行为 | 第一版示例 |
| --- | --- | --- | --- |
| 素材输入 | `source` | 用户选择或导入文件，节点只建立受管理的资产修订 | 角色参考图、动作视频 |
| 本地自动 | `automatic` | 动作工坊可以直接调用本地执行适配器产生结果 | 提取序列帧、移除背景、导出游戏资产 |
| 人工编辑 | `interactive` | 用户进入专注工作区编辑并明确确认结果 | 整理序列帧、制作动作片段、组装角色资产 |
| 外部处理 | `external` | 为未来外部任务保留；当前没有此模式的内置节点 | 后续外部工具任务 |

执行模式属于节点定义，不由执行器猜测。外部处理节点第一版不假装知道外部工具是否正在运行，只记录当前输入签名、生成要求和已导入结果。

### 资产

资产是节点之间流动的数据。连线保存的是资产引用和修订关系，不复制一份文件。

第一版资产类型：

| 中文名称 | 协议类型 | 内容 |
| --- | --- | --- |
| 角色参考图 | `reference-image` | 角色外观与跨动作一致性参考 |
| 动作视频 | `action-video` | 一段动作的视频素材 |
| 原始帧集 | `frame-set/source` | 带稳定帧ID、顺序和来源信息的图片集合 |
| 透明帧集 | `frame-set/transparent` | 带Alpha与精修修订的图片集合 |
| 动作片段 | `action-clip` | 帧、节奏、循环、画布、原点、变换和事件 |
| 角色资产 | `character-asset` | 同一角色的多个动作和共享基准 |
| 引擎资产包 | `engine-package` | 面向指定目标生成的派生文件集合 |

### 编辑器

编辑器是修改节点参数或节点所处理资产的界面，不是独立数据源，也不是另一套产品状态。

例如“整理序列帧”是节点，帧集是它的输入和输出；排序、删除、恢复、循环查找和播放检查组成该节点的帧工作区。关闭工作区后仍回到原节点，修改形成该节点的新输出修订。

### 项目图与执行图

项目保存的是用户可编辑的工作流图，包含节点、稳定端口名、连线、参数、位置、分组、视口和资产修订。运行某个目标节点前，再从项目图编译出只包含该目标及其上游依赖的执行图。

- 执行器不依赖节点坐标、缩放、选中状态或界面是否打开。
- 画布允许保留未连接草稿；草稿不阻止其他完整分支运行。
- 第一版节点类型来自代码内置注册表。用户可以自由创建、删除、复制、配置和连接这些节点实例，但暂不开放自定义节点插件或任意脚本节点。
- 节点注册表只声明端口、参数结构、执行适配器和版本；抽帧、抠图、导出等领域实现继续通过适配层复用已有核心，不在画布层复制业务逻辑。

## 第一版节点目录

### 1. 角色参考图

- 输入：无。
- 参数：图片文件、角色名称。
- 输出：`reference-image`。
- 深度编辑：裁切、基准尺寸等后续再设计。

### 2. 动作视频

- 输入：可选的一个`reference-image`；不连接时也能独立导入。
- 素材：用户在工具外生成或拍摄后导入的视频，执行模式为`source`，不在本工具内生成。
- 可选备注：动作描述、方向、期望时长和外部工具备注，默认折叠；期望时长不替代视频实际时长。
- 输出：`action-video`。浏览器可解码的MP4、WebM、MOV，上限256 MiB，显示实际尺寸与时长，不猜测来源帧率。
- 已实现：选择/拖入、播放、更换、本机素材库刷新恢复；取消导入或失败不替换原素材。
- 关联参考图、备注或连接变化后，已有视频及可达下游待更新。旧视频仍可播放，重新导入或明确确认“采用当前视频”后仅恢复视频就绪；确认弹窗取消不修改状态。
- 后续接入视频生成服务时再增加明确的生成适配能力，不恢复两个职责重复的导入入口。

### 3. 提取序列帧

- 输入：一个`action-video`。
- 参数：开始时间、结束时间、采样帧率。
- 输出：`frame-set/source`。
- 深度编辑：视频范围和抽帧结果检查。

### 4. 整理序列帧

- 输入：一个帧集，类型可以是`frame-set/source`或`frame-set/transparent`。
- 参数：播放速度、循环范围。
- 输出：保持输入类型的帧集。
- 深度编辑：排序、删除、恢复、循环候选和播放检查。
- 不变式：整理只改变帧集合的组织信息，不丢失原图或Alpha属性。

### 5. 移除背景

- 输入：一个`frame-set/source`。
- 参数：模型、FFmpeg去绿及边缘参数。
- 输出：`frame-set/transparent`。
- 深度编辑：批量结果检查；双击单帧进入人工精修弹窗。

### 6. 制作动作片段

- 输入：一个`frame-set/transparent`。
- 参数：动作名称、是否循环、播放节奏、共享画布、原点、整组变换和事件。
- 输出：`action-clip`。
- 深度编辑：动作播放、原点与变换、逐帧时长和事件。

### 7. 组装角色资产

- 输入：零或一个`reference-image`，以及一个或多个`action-clip`。
- 参数：默认动作、动作命名映射和共享基准。
- 输出：`character-asset`。
- 深度编辑：跨动作叠图、尺寸、脚底位置和原点统一。

### 8. 游戏预览

- 输入：一个`character-asset`。
- 参数：目标运行时、背景、初始动作和播放条件。
- 输出：不产生新的编辑真值；只建立可关闭的预览会话。
- 深度编辑：Godot或JavaScript实际运行预览。

### 9. 导出游戏资产

- 输入：一个`character-asset`。
- 参数：目标格式、单帧尺寸、图集布局、目标引擎和输出目录。
- 输出：`engine-package`。
- 不变式：导出包是派生结果，不能反向覆盖角色项目。

## 连接规则

连接是否合法由端口类型、输入数量和图结构共同决定，不按固定页面阶段写死。

| 上游输出 | 允许连接的下游输入 |
| --- | --- |
| `reference-image` | 动作视频、组装角色资产 |
| `action-video` | 提取序列帧 |
| `frame-set/source` | 整理序列帧、移除背景 |
| `frame-set/transparent` | 整理序列帧、制作动作片段 |
| `action-clip` | 组装角色资产 |
| `character-asset` | 游戏预览、导出游戏资产 |
| `engine-package` | 第一版没有下游节点 |

### 数量约束

- 提取序列帧、整理序列帧、移除背景、制作动作片段、游戏预览和导出游戏资产的主输入均只能连接一个上游。
- 动作视频允许不接参考图；关联参考图时最多连接一个。
- 组装角色资产允许零或一个角色参考图，以及一个或多个动作片段。
- 同一个输出可以连接多个下游，形成显式分支。

### 拖线反馈

用户从端口开始拖线时：

1. 兼容的输入端口高亮。
2. 不兼容节点变暗。
3. 悬浮非法端口时说明原因，例如“需要动作视频，当前输出为角色参考图”。
4. 在空白处松开时，只展示能接收当前输出类型的节点列表，并允许创建后自动连接。

### 成环限制

工作流第一版必须是有向无环图。即使两个功能在不同工作流里可以交换顺序，也不能在同一分支里首尾互连形成循环。

整理与抠图允许两种合法顺序：

```text
提取序列帧 → 整理序列帧 → 移除背景
提取序列帧 → 移除背景 → 整理序列帧
```

但不允许：

```text
整理序列帧 → 移除背景 → 整理序列帧
       ↑_____________________|
```

## 执行与状态传播

节点只有在以下条件全部成立后才能运行：

1. 必填输入已连接。
2. 输入资产存在且类型正确。
3. 参数通过运行时校验。
4. 上游结果修订可用。
5. 当前执行不会形成资源或安全冲突。

统一状态：

- `未连接`：缺少必填输入。
- `待配置`：输入完整但参数不完整。
- `可运行`：满足运行条件，尚无当前输入对应结果。
- `等待操作`：人工编辑节点需要用户进入工作区完成或确认。
- `等待外部结果`：外部处理节点尚未导入与当前输入签名对应的结果。
- `待确认`：人工修改或外部结果已经产生，等待用户确认采用。
- `运行中`：任务正在执行。
- `已完成`：输出对应当前输入与参数修订。
- `待更新`：上游资产、本节点参数或节点实现版本已变化；当前旧结果仍可查看，但不再代表当前工作流。
- `失败`：运行失败并保留明确错误。

### 失效传播

上游输入、节点参数或节点实现版本发生变化后，当前节点及所有直接或间接依赖它的下游节点沿连线标记为“待更新”。失效只沿依赖关系传播，不影响没有依赖该结果的其他分支。

例如：

```text
角色参考图 → 动作视频 → 提取序列帧 → 整理序列帧 → 移除背景 → 制作动作片段
```

更换角色参考图后，从已关联的“动作视频”开始的下游已有结果都进入“待更新”；角色参考图节点自身持有的是新输入，因此不标记为旧结果。未关联的独立视频不受影响。旧视频、旧帧和旧动作片段暂时保留，但不能静默作为当前结果继续交付。

### 增量执行与结果复用

本节为后续通用调度器设计，并非当前画布自动执行能力。当前自动执行仅编排已接通的帧处理分支，缺输入时禁止启动，人工精修不暂停流程；不提供本节的通用人工/外部暂停与恢复机制。实际范围见[自动执行索引](references/workflow-auto-implementation.md)。

用户运行某个目标节点时，系统不默认从源头全部重跑，而是：

1. 从目标节点反向收集本次必需的上游依赖。
2. 按拓扑顺序检查每个依赖节点的结果签名和输出是否仍然有效。
3. 输入资产修订、节点参数、节点实现版本均未变化且输出仍存在时，直接复用已有结果。
4. 从每条依赖路径上最早的失效节点开始重新执行，直至目标节点。
5. 某个节点成功后生成新的输出修订；依赖它的后续节点再使用这个新修订继续执行。
6. 某个节点失败时，停止所有依赖它的后续节点；无关分支不受影响。

如果执行范围遇到尚未完成的素材输入、人工编辑或外部处理节点：

1. 自动执行在该节点暂停，不跳过，也不使用与当前输入签名不匹配的旧结果。
2. 画布选中该节点并显示所需操作；人工节点打开工作区，外部节点提供生成要求和“导入结果”入口。
3. 用户完成编辑或导入结果后先检查并明确确认。
4. 节点生成与当前输入签名绑定的新输出修订，然后从该节点继续原目标的剩余下游。

第一版不会在用户导入外部结果后未经确认自动运行整条下游。用户使用“确认并继续”恢复原目标，或只保存结果稍后再运行。

结果签名至少由以下内容组成：

- 所有输入资产的稳定ID与修订；
- 当前节点参数；
- 节点功能实现版本；
- 输出资产是否仍然存在且可读取。

线性流程中的例子：如果只修改“整理序列帧”的参数，运行“制作动作片段”时复用角色参考图、动作视频和原始帧集，只执行“整理序列帧 → 移除背景 → 制作动作片段”。如果全部签名仍然一致，则直接复用目标结果。界面后续提供显式“强制重新运行”，但它不是默认行为。

外部生成例子：已关联的参考图或动作备注发生变化后，“动作视频”节点原来导入的视频进入“待更新”，已有下游结果也随之待更新。用户可以重新导入，或明确确认采用当前视频；取消确认不改变状态。独立视频不受其他参考图变化影响。当前已实现上述本机状态传播，但完整输入签名、运行下游暂停/续跑仍待执行器实现；当前素材结果签名只保存文件内容哈希。

## 数据真值与保存

- 工作流项目、资产引用和修订记录是长期真值；浏览器组件状态、预览会话和内存缓存都不是长期真值。
- 节点状态由连接、参数、输入修订和输出是否存在共同推导，不设置一个含糊的“整个项目已完成”开关。
- 专注工作区中的有效修改写入所属节点的新输出修订；返回画布不触发额外“导入”或复制资产。
- 更换参考图、动作视频或重新抽帧等操作执行前，应列出将进入“待更新”的下游节点和受影响资产；确认后才切换输入修订。
- 保存失败时保留当前编辑上下文并显式报错，不能显示“已保存”，也不能静默回退到旧页面或旧缓存。
- 游戏预览和导出包都是可重新生成的派生结果，不能反向覆盖项目图、原始素材或人工精修结果。

## R6-A 协议与 R6-B 画布落点

R6-A 已把上述设计固化为可执行协议，R6-B 已在该协议上实现正式画布基础，但还没有实现服务端项目仓库或节点执行器：

- 运行时模型和内置节点注册表：`app/workflow_schema.py`。
- 可版本化项目格式：`formatVersion: 1`、`kind: action-forge-workflow`。
- 生成的结构 Schema：`docs/schemas/workflow-project-v1.schema.json`。
- 可回读样例：`docs/examples/workflow-project-v1.valid.json`。
- 连接和语义回归：`tests/test_workflow_schema.py`。
- 正式画布入口：`/workflow`，实现为`web/workflow.html`、`web/workflow.css`和`web/workflow.js`。
- 浏览器画布领域逻辑：`web/workflow-core.js`；生成节点目录：`web/workflow-node-registry.json`。
- 画布回归：`tests/web/workflow-core.test.mjs`和`tests/browser/workflow-canvas.spec.js`。

校验分为两层：JSON Schema负责字段、枚举和基础形状；Python运行时模型继续负责节点定义版本、参数模型、稳定端口、连接数量、类型透传、资产修订引用和有向无环等跨字段语义。不能只通过JSON Schema就宣称项目可执行。

工作流项目允许保存未连接或参数未填完的草稿。R6-B把名称、节点、参数、位置、连线和视口写入浏览器本机草稿，刷新可恢复；它不是服务端项目仓库，不能跨浏览器或清理站点数据恢复。运行目标前使用`inspect_execution`检查目标上游闭包，结构化报告缺少输入、缺少参数以及等待素材、人工或外部结果；非法端口、类型不兼容、超量连接、重复连接、自连接和依赖环则在项目校验时直接拒绝。R6-C才会实现结果签名计算、待更新传播、执行、暂停与恢复，本阶段不伪造这些能力。

## 画布与工作区的交互

- 单击节点：选择节点，在右侧检查器编辑轻量参数。
- 拖动端口：创建受类型约束的连接。
- 点击运行：反向检查当前节点需要的上游，复用有效结果，仅重新执行待更新或缺少结果的依赖和当前节点。
- 双击节点：进入该节点的专注工作区。
- 返回画布：恢复之前的平移、缩放、选择和连线视图。
- 单帧精修等范围明确的任务使用弹窗，关闭后返回所属节点工作区。

## 视觉基调

动作工坊的正式页面采用专业、沉稳、克制的工具软件风格，以黑、灰、白为主，不使用花哨渐变、玻璃拟态、大面积高饱和色或装饰性插画。

- 画布使用近黑或深炭灰背景，网格和辅助线保持低对比度。
- 节点、检查器和弹窗使用分层灰阶区分层级，以细边框和留白建立结构，不依赖厚重阴影。
- 主文字使用柔和白色，次级信息使用中性灰；禁用状态必须仍然可读。
- 品牌色和状态色只用于选中、端口类型、运行中、成功、待更新和失败等必要反馈，不大面积铺色。
- 同类节点保持统一结构、尺寸和端口位置；优先显示名称、状态、关键值和操作，减少重复说明。
- 图标采用统一线性图标体系，不使用含义不明的自绘符号；图标不能替代必要文字。
- 动效只服务于连线、执行进度、状态变化和工作区切换，避免持续闪烁和无意义动画。

## 第一条产品纵向流程

第一版先跑通一条最短但真实的流程：

```text
动作视频（导入外部文件）
    ↓
提取序列帧
    ↓
整理序列帧
    ↓
移除背景
    ↓
制作动作片段
    ├────────────────┐
角色参考图 ──────────┴→ 组装角色资产
    ├→ 游戏预览
    └→ 导出游戏资产
```

视频生成服务暂不接入；统一动作视频节点先接入外部文件，不阻塞纵向流程。

## 暂不进入第一版

- 自定义节点插件和任意脚本节点；这不影响用户在画布上创建和配置内置节点实例。
- 底层模型、前景估计和FFmpeg拆成多个算法节点。
- 循环图、条件分支和状态机。
- 多人协同编辑。
- 对不存在的正式历史项目做迁移兼容。
