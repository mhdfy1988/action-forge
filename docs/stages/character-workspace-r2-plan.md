# R2 共享画布与跨动作校准计划

## 状态

R2已完成。严格协议、共享几何计算、校准弹窗、双动作真实PNG交互、整组播放与调整、项目实际保存重开和旧链路回归均已通过。第一条纵向流程为：同一角色选择“跑步”基准帧，设置共享画布原点；切换到“跳跃”，在叠图中标记同一角色锚点，并用动作级缩放/偏移校准整组帧；保存、重开后画布和两动作校准均恢复。

## 目标与选择原因

解决不同视频生成的跑步、跳跃动作在游戏里大小不一、脚底位置跳动的问题。采用人工选定基准帧和动作锚点，并对动作整组应用非破坏缩放/偏移。先把坐标与保存规则跑通，再考虑自动检测；不通过逐帧居中抹掉跳跃高度、手臂摆动等真实动作。

## 第一版数据语义

- 角色`canvas`是所有动作共用的像素画布；角色`origin`是画布内固定参考点，坐标原点在左上角，X向右、Y向下。
- 角色保存一个`baseline`：稳定的基准动作ID和基准帧ID。删除或禁用该帧时必须清除/重选基准，不能留下悬空引用。
- 每个动作保存`anchor`：该动作校准帧ID，以及该帧内归一化坐标（0到1）。同动作所有帧沿用该锚点位置，因为视频源帧保持相同像素画布；不逐帧改写锚点。
- 动作现有`transform.scale`与`transform.offset`作为整组变换。源图保持原字节；预览和导出在共享画布上应用角色缩放、动作缩放/偏移和锚点定位。
- 基准动作默认变换为单位缩放、零偏移；基准帧的锚点与角色原点重合。其他动作的锚点可经叠图校准到同一原点。
- 不同源视频分辨率按各自图像尺寸适配共享画布，适配比例只作为显示/导出几何的一部分；用户再用动作级比例修正不同视频中主体尺寸差异。

## 具体操作流程

1. 打开角色项目，检查动作列表；第一版选择跑步作为基准动作。
2. 设置共享画布宽高。默认可从当前动作源帧尺寸建议，但由用户确认后保存。
3. 选择跑步中的一帧作为基准帧，在预览画布上标记脚底中心等稳定身体锚点；选择画布内对应原点。
4. 切换到跳跃，选择适合对齐的校准帧；基准帧以半透明方式叠加显示，当前动作帧显示在前。
5. 在当前帧上点选同一身体锚点，再调节动作整组缩放和X/Y偏移；播放当前动作，确认锚点位置稳定且跳跃高度仍保留。
6. 保存项目，刷新或服务重启后重新打开；确认共享画布、原点、基准帧和跳跃变换一致。

第1个动作只建立画布与基准锚点；第2个动作通过叠图校准尺寸和位置；第N个动作复用同一画布原点，分别保存自己的锚点和整体变换。任何动作内部的运动轨迹都不被自动压平。

## 状态变化

```text
未校准 → 设置画布/基准帧 → 标记基准锚点与原点 → 标记动作锚点
        → 调整整组变换 → 预览确认 → 已保存
                                   └→ 保存失败（保留草稿）
```

基准变更、画布变更、锚点点击和动作变换都标记项目为未保存。动作切换不自动保存；沿用R1的显式保存与未保存离开提示。

## 不变式与边界

- 画布与角色原点同时存在；基准动作/帧必须属于当前角色，且基准帧启用。
- 动作锚点必须引用该动作中存在且启用的帧；归一化坐标在0到1范围内。
- 所有图片变换围绕各动作保存的锚点映射到同一个角色原点；基准动作锚点固定于原点。
- 只变换预览/派生输出，不覆盖`source`、`mattingBase`或`current`图片。
- 调节只作用于当前动作的所有帧，不能改写角色画布、角色原点或兄弟动作参数。
- 首版只提供人工校准与叠图；自动人体/脚底识别、逐帧变换、骨骼、碰撞框、Godot同步留到后续阶段。
