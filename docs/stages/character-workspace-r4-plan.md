# R4 动作编排与事件

## 状态

R4-A 至 R4-E 已全部完成。项目清单已从 v1 显式升级到 v2，工作区可编辑逐帧时长和事件，支持按节奏播放、循环触发记录、中立角色包导出及 Godot 预览验证。正式写入用户游戏工程仍不属于本阶段。

## 目标与原因

让一套动作从“按固定速度播放的一串图片”成为可编辑、可预览、可移交给游戏的动作资产：可确定播放节奏，在具体帧上标记游戏可消费的事件，并能验证帧顺序、循环边界和事件时机。

选择先在角色工作区内完成，是因为事件和时长依赖稳定帧身份、帧顺序、启用状态及动作循环规则；若先做独立引擎导入器，就会再次分叉核心语义。R3 Godot 预览桥保持只读，R4 不把编辑动作转成对用户游戏工程的隐式写入。

## 现状核对

- v1 动作已有 `loop`、`playback.mode = constant-fps`、`fps`、稳定帧 ID 与 `events[]`；当前严格协议为 v2。
- 当前 `ActionEvent` 字段为 `id`、`frameId`、`type`、`parameters`；事件在目标帧开始时发生，必须引用同动作启用帧，单事件参数上限为 16 KiB。
- 严格模型已拒绝重复事件 ID 与指向不存在/禁用帧的事件；工作区对禁用关联帧显式确认，并同时移除该帧事件及锚点/基准引用。当前不提供物理删除单帧入口。
- 帧数组顺序就是播放顺序；启用帧参与播放与生成，来源帧及资产不得因整理操作被覆盖。
- Godot 实时预览协议 v2 快照包含播放规则、逐帧时长和事件；浏览器播放时 Godot 镜像帧切换，Godot 本地播放时按同一数据推进，并只记录帧进入事件。
- 项目协议严格拒绝未知字段。v1 只读时内存升级，不改写磁盘；首次成功保存时写入 v2，未知版本快速失败。

## 第一版范围

### 纳入

1. **播放节奏**：保留固定帧率模式；增加逐帧时长模式。每个启用帧拥有明确正时长，播放总时长由启用帧时长求和，禁用帧不计入。帧顺序仍以数组位置为准，不另存容易冲突的序号。
2. **事件标记**：在帧序列/时间轴上查看、添加、编辑、移动和删除事件；事件锚定稳定 `frameId`，帧换序后仍跟随同一帧。事件可并列锚定同一帧，顺序由事件自身在动作数组中的顺序稳定保存。
3. **帧变更保护**：禁用有事件的帧时明确确认，继续后移除关联事件与依赖它的锚点/基准引用；取消则保持原样。恢复帧只恢复帧启用状态，不会自动恢复已清理事件。当前没有单帧物理删除入口。
4. **动作预览**：按实际播放时长预览启用帧和循环；最近事件记录显示实际播放累计时间，便于检查首帧、普通帧和循环回到首帧时机。事件预览只演示资产事件，不执行游戏战斗、音效或状态机逻辑。
5. **可交付数据**：导出 ZIP 包含规范化 v2 `project.json` 和清单引用的原始/抠图/精修/参考素材，目录结构保持项目相对路径；不打包可再生 `generated/`，不修改项目目录。Godot 适配器只映射数据并辅助验证，不直接修改用户游戏工程。

### 暂不纳入

- 游戏输入绑定、角色状态机、伤害判定、音频播放、技能逻辑或 AI。
- 碰撞框/受击框逐帧绘制、骨骼动画、动作混合、根运动。
- 自动推断事件、自动动作切换或由视频来源时间控制游戏播放速度。
- 在 R4 中接管用户项目目录或写入正式游戏工程；这需要独立的应用/导入流程和目标工程确认。

## 数据与协议决策

- 事件继续使用引擎中立的稳定帧引用；不把 Godot 节点路径、信号名、JavaScript 回调或资源绝对路径写进核心协议。
- 事件含义先用轻量 `type` 字符串和受限 JSON `parameters` 表达。第一版界面优先给常用类型快捷模板（如脚步、命中、特效）并允许自定义类型；模板只是输入辅助，不改变核心协议含义。
- 固定帧率下每帧时长由 `1/fps` 推导。逐帧模式下时长以精确有理数保存，界面可用毫秒显示；不将浮点秒作为持久化真值。
- 版本处理：实施前给项目清单显式升级版本。v1 固定帧率动作迁移后仍保持相同节奏；升级后必须可往返保存/重开，未知版本仍快速失败。不要静默 fallback 到旧路径。
- 修改事件或逐帧时间只增加所属动作修订；不得改变兄弟动作修订、帧图像字节、原视频来源信息或角色共享画布/原点。

## 操作流程与状态变化

```text
打开已保存动作
  → 选择固定帧率 / 逐帧时长
  → 调整帧顺序、启用状态和时长
  → 在目标帧添加/修改事件
  → 播放并观察总时长与事件记录
  → 保存动作草稿
  → 刷新/重开确认回读
  → 导出中立资产 / 在 Godot 预览中核对
```

例如第 1 轮，跑步动作保持 12 fps，在左脚落地帧添加 `footstep`；第 2 轮，把该帧与前一帧交换，事件仍跟随原帧 ID，播放记录的触发位置随帧顺序变化；第 N 轮，改成逐帧时长，事件触发时刻按此前启用帧的时长累计，并在循环回到首帧时再次触发。

编辑过程是未保存草稿；保存成功后动作修订递增。刷新/重开后数据一致。导出失败不得将状态标成已导出或回退成不含事件的静默旧产物。

## 不变式和边界

- 仅启用帧参与播放、总时长和事件触发；帧 ID 是事件锚点，不是可变序号。
- 循环播放在每次进入目标帧时触发其事件；事件语义不依赖渲染帧率。暂停不触发，播放头跳转/编辑器拖动默认不触发游戏事件，只改变预览位置。
- 被禁用/删除帧的事件必须显式处理；动作、角色或项目删除也不得遗留独立事件。
- 固定帧率和逐帧时长同一时刻只能选一种有效播放规则；总时长来自所选规则，源视频时间只是来源元数据。
- 编辑真值仍是角色项目；Godot/JS 数据均为可再生派生物。R4 的引擎预览验证不授予写用户工程权限。
- 事件记录是验证界面而不是游戏运行时；不宣称已经完成引擎内游戏行为接入。
