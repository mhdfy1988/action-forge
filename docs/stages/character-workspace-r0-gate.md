R0只确定新角色项目的领域边界，未添加角色工作区页面、工程读写入口、迁移按钮或Godot连接。当前8897单动作路径保持原行为。以下文档与校验器是R1的实施依据：

| 工作包 | 交付 | R0验证 |
| --- | --- | --- |
| A 协议 | [角色资产协议](../character-asset-protocol.md)、合法与非法JSON样例、`app/character_project_schema.py` | 双动作合法样例可往返；非法重复ID、越界路径拒绝。 |
| B 保存 | [项目保存与恢复](../character-project-storage.md) | 固定不可变图片、清单最后提交、失败恢复和修订冲突语义。 |
| C 迁移 | [旧结果迁移](../legacy-action-migration.md) | v2/v3/v4输入映射、幂等凭据、缺失输入和目标冲突规则。 |

## 运行时校验边界

`CharacterProject`通过Pydantic严格拒绝未知字段、未知格式版本、重复角色/动作/项目帧ID、事件悬空、无效画布/原点、不安全路径和跨角色资产目录。`validate_project_assets`核对清单引用文件存在、位于项目内、PNG可解码，透明结果具有Alpha通道；这不是保存仓库，当前不执行任何写盘。未来R1项目仓库必须在打开和保存时调用这些校验，不能只在测试中使用。

## R1必做测试清单

- 新建项目 → 加入`run`和`jump` → 保存 → 关闭重新打开 → ID、名称、顺序、FPS、循环、基准和修订保持一致。
- 修改`jump`后`run`的编辑内容与修订不变；项目、角色和`jump`修订按规则递增。
- 精修图片保存中断、图片就位但清单未提交、清单提交后回执丢失，都能按磁盘清单确定唯一真值。
- `expectedRevision`过旧时明确冲突，不覆盖；外部进程锁/Windows替换失败时保留原工程。
- 缺源PNG、坏PNG、图片越根、未知版本、重复ID、事件引用禁用帧明确失败；缺抠图可导入但不能标为透明资产。
- 旧v2/v3/v4清单与图片迁移后ID、顺序、来源有理时间、抠图/精修结果与哈希一致；原缓存字节不变。
- 同输入重复迁移返回已导入，导入后已编辑项目不被覆盖；不同输入占同一路径返回冲突。
- 未校准角色可以打开编辑，但正式引擎快照及“游戏资产就绪”状态必须拒绝或提示校准。
- 新功能通过独立入口或隔离容器接入；当前抽帧、整理、抠图、精修、导出回归全绿。

## R1实施顺序

1. 先建立`ProjectRepository`与上述校验器之间的适配；确认跨进程文件锁方案，完成故障注入测试。
2. 再做旧结果迁移器，结果只写新项目目录，不改旧会话。
3. 最后接独立角色工作区，首个纵向用例是同一角色的跑步和跳跃能独立编辑、保存、回读。
4. 共享画布校准属于R2；引擎实时连接属于R3；逐帧时长和动作事件的可视编辑属于R4。R1不能以预览协议已有为由宣称这些功能完成。

## 准入结论

R0当时已通过协议样例与旧链路测试并准入R1。后续R1实现已完成真正的项目仓库、迁移器与双动作界面验收；该结论仍不等于R2跨动作校准或R3引擎连接已经可用。
