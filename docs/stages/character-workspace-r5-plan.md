# R5 计划：JavaScript 动作资产适配器

## 状态

R5-A至R5-D已于2026-10-09完成。实现位于 `integrations/javascript/`，读取R4角色ZIP解压目录，不写用户游戏工程。真实ZIP、双动作、两种播放模式、事件、共享几何、透明像素和输入只读门禁均已通过；本文件同时保留原始边界，作为后续验收依据。

## 目标

让 R4 生成的项目中立角色资产可以由普通 JavaScript 宿主直接读取并播放，形成“动作工坊资产包 → JavaScript 适配器 → 可运行示例”的第一条非 Godot 消费链路。用户能看到动作切换、帧播放、循环、逐帧时长、共享画布/原点/变换和事件触发；这证明资产包能被游戏侧消费，但不等于已接入用户的正式游戏工程。

选择这条纵向切片，是因为 R4 已经提供角色 ZIP、v2 清单和事件语义，直接做适配器能验证协议是否真的可用；先不并入碰撞框、攻击拖尾等高级编辑能力，避免一阶段同时改格式、编辑器与多个运行时。

## 第一版边界

包含：

- 一个隔离的 `integrations/javascript/` 适配器，不把 JavaScript 或具体游戏框架类型带入角色资产核心。
- 从用户明确解压的 R4 角色资产包读取清单及相对路径 PNG；不在适配器中隐式解压 ZIP，也不请求动作工坊服务端。
- 严格校验支持的角色资产版本、清单字段、引用路径、帧和事件；不支持或无效输入显示具体错误并停止加载。
- 公开清晰的最小运行接口：加载角色资产、选择动作、播放/暂停、逐帧推进、设置播放速度、订阅事件、销毁资源。
- 一个无特定游戏框架依赖的 JavaScript 示例宿主，证明开发者可将适配器接入自己的循环/渲染层。
- 自动化测试覆盖固定帧率和逐帧时长、循环与非循环结束、动作切换、帧事件触发时刻、禁用帧跳过、迟到/无效输入及资源清理。

不包含：

- 写入、自动改造或安装到用户的真实游戏工程；也不宣称完成某个具体 JavaScript 游戏引擎插件。
- 游戏输入映射、角色状态机、战斗/碰撞判定、AI、动画混合、网络同步。
- 碰撞框编辑、攻击拖尾、附加图层、逐帧特效烘焙和图集优化；这些候选项等 JS 消费链路验收后再单独定范围。
- 为了适配而静默修复或回退旧版清单；遇到不支持版本必须清楚失败。

## 流程与状态

```text
R4角色ZIP
  → 用户解压并选择 project.json 与资产根目录
  → 适配器严格校验清单/路径/PNG
  → 已加载角色（只读快照）
  → 选择动作
  → 播放时钟推进启用帧并按事件语义发出通知
  → 示例宿主渲染共享画布上的当前帧
```

输入是 R4 中立角色资产清单与其相对路径引用的图像。输出是运行时只读角色对象、当前动作/帧、事件通知及可供宿主渲染的图像引用；适配器不得改写项目清单或源 PNG。动作切换时清零当前动作播放游标；固定帧率由 `1/fps` 计算帧时长，逐帧模式按每个启用帧的 `duration` 推进；循环动作回到首个启用帧，非循环动作到末帧后停在末帧。事件在目标启用帧开始时最多触发一次；跨过多个帧时必须按播放时间顺序补发，暂停时不推进、不发事件。

第一轮：加载 `run` 与 `jump` 两个动作，示例宿主完成切换和播放，证明两个动作共享同一画布/原点且变换一致。

第二轮：给 `run` 配置脚步事件、给 `jump` 配置起跳事件，验证固定帧率与逐帧时长都在正确时刻触发，暂停和动作切换不会重复触发旧动作事件。

第 N 轮：输入超出支持范围、缺失 PNG 或帧引用无效时，加载明确失败并可销毁/重新加载；不会显示旧帧冒充新资产，也不会写回输入包。

## 接口与不变式

- 运行时协议仍以 `docs/character-asset-protocol.md` 的角色资产 v2 为真值；如 R5 发现协议缺口，先提议版本化协议变更，不私自扩展解释。
- PNG 路径只能是包内安全相对路径；拒绝绝对路径、路径穿越、重复 ID、悬空事件/帧引用和超出资源预算的图像。
- 帧顺序、启用状态、循环、逐帧时长和事件发生语义与 v2 一致；来源视频时间不是播放时间。
- 绘制几何复用中立画布、原点、角色比例和动作变换定义；适配器不做逐帧自动居中/紧裁。
- 加载、播放、停止、切换、错误和销毁状态显式可观察；任何错误不得静默使用旧数据。
- 引擎/宿主只接收帧和事件，不获得修改项目数据的隐式能力。

## 工作包与退出门禁

1. [x] R5-A：核对 R4 ZIP 的真实布局及浏览器/Node 文件读取边界，定下公开接口、资源上限和错误类型；Ajv仅作为生成静态校验器的开发依赖。
2. [x] R5-B：实现无框架运行时适配器与严格输入校验；播放和几何由共享核心与薄转发复用，没有复制第二套规则。
3. [x] R5-C：实现隔离示例宿主和真实 R4 导出包端到端验证；使用独立8898与`output/r5-final-*`数据目录，未接管8897/5180。
4. [x] R5-D：完成Node、Python、Chrome全量回归、ZIP解压回读、事件时序、透明像素、输入哈希不变和文档同步。

退出条件：真实 R4 ZIP 可在示例宿主中加载；两个动作可切换和播放；循环、非循环、固定帧率、逐帧时长、事件时序、共享画布/原点和变换均有自动化证据；无效版本/缺图/越界路径显式失败；输入包未改变；完整既有回归通过。此门禁通过只代表 JavaScript 示例适配器可用，不代表正式接入任一用户游戏工程。

## 收口证据

- 静态校验器连续生成SHA-256一致；41项Node领域测试全部通过，其中包含浏览器约16毫秒小步时钟累计、缺引用文件和销毁态回归。
- 81项Python测试通过，1项需要私有真实模型的条件测试跳过。
- 全新隔离项目/缓存目录上的Chrome完整回归42项通过、1项真实模型条件测试跳过。
- 真实API导出ZIP经Python解压，浏览器文件夹入口成功读取；`run`固定10帧/秒循环和`jump`逐帧时长非循环均播放并触发事件。
- Canvas读取到透明及非透明像素；解压前后`project.json`哈希一致，服务端项目回读也未变化。
- 示例截图：`output/acceptance/action-forge-r5-javascript.png`（本机验收产物，不提交仓库）。
- 适配器用法和资源边界见[`integrations/javascript/README.md`](../../integrations/javascript/README.md)，Ajv决策与源码落点见[JavaScript源码证据索引](../reference-javascript-runtime.md)。

## 后续候选

R5 通过后，另行决定是否做具体引擎插件，以及碰撞框、攻击拖尾、图层等高级资产。届时先明确目标引擎/项目和用户授权范围，再依据该引擎官方资料核对导入与运行接口；不将这些功能自动塞入 R5。
