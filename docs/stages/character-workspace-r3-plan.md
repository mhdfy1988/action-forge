# 角色工作区 R3：Godot 实时预览计划

## 目标与取舍

目标是让角色项目的编辑态能在 Godot 原生预览窗实时查看，并完成双动作切换与重连验收。先建立回环本机预览桥和最小 Godot 客户端，而不是立即写入用户游戏工程：这样可先验证角色数据、画布/原点/动作变换与引擎显示的映射，避免把尚未稳定的项目协议污染到真实游戏工程。

第一版只对接已保存帧资产，浏览器内未保存的动作/帧结构变更不进预览；可同步编辑态空间参数、动作/帧选择和播放状态。持久化仍只通过角色项目保存 API，预览桥本身只读。

## 流程、输入输出与状态

```text
已保存角色项目 + 当前编辑态
  -> 浏览器创建本机短期会话
  -> 浏览器发布严格校验的快照
  -> Godot 用 WebSocket 配对并接收快照
  -> Godot 通过只读帧端点取图，显示共享画布/原点/动作
  -> Godot 确认修订
  -> 编辑态变化发布新快照 -> 引擎更新
```

输入：项目 ID、角色/动作/帧选择、播放标志、共享画布与原点、角色和动作变换、已保存帧资产。
输出：Godot 预览图像、动作播放和最新已确认修订；无项目清单写入、无用户工程文件写入。

状态：`无会话 → 等待配对 → 等待快照 → 已同步 → 等待确认 → 已同步`；断开后会话仍短期有效，重新连接后完整快照恢复；到期/应用退出后回到无会话。

不变式：只监听 `127.0.0.1`；令牌仅内存持摘要、仅授权单会话；所有帧按清单帧 ID 查询；客户端不能给文件路径或任意 URL；快照必须运行时校验且帧引用属于该项目；预览不静默使用旧帧掩盖错误。
