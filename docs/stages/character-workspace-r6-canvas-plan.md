# R6 可操作工作流画布计划

## 当前结论

动作工坊从空项目开始构建完整产品，不背负测试阶段产生的历史项目、旧页面流程或迁移数据。R0至R5只证明抽帧、整理、抠图、动作协议和引擎预览等技术组件可行，不等于已经存在完整产品。

新版产品以可操作工作流画布为主界面：用户在画布上创建、连接、配置和运行节点。节点是功能实例，资产通过强类型端口流动；复杂操作从节点进入专注工作区，单帧精修等单点任务使用弹窗。

完整节点、资产和连接协议见[工作流画布与节点模型](../workflow-canvas-node-model.md)。

## 产品结构

### 画布

- 是产品的主要操作界面，不是只读投影。
- 支持创建、删除、移动、复制和连接节点。
- 支持运行单节点、分支和完整工作流。
- 保存工作流结构、参数、画布位置和资产修订。

### 右侧检查器

- 显示当前节点的输入、输出、参数、状态和错误。
- 编辑轻量参数，不复制复杂工作区。

### 专注工作区

- 由节点双击或主操作打开。
- 用于帧整理、动作调整、跨动作校准和引擎联调等复杂任务。
- 返回后恢复画布位置、缩放和选中节点。

### 单点弹窗

- 用于单帧精修、循环候选对比和危险操作确认。
- 不承担完整动作的连续制作流程。

## 产品不变式

- 节点是功能实例，资产不是节点，编辑器不是第二套数据源。
- 端口按资产类型、连接数量和无环规则校验。
- 工作流和资产修订是项目真值，画布不是对旧页面状态的包装。
- 上游结果、参数或节点实现版本变化后，相关下游显式标记为“待更新”，无关分支不受影响。
- 运行目标节点时反向收集依赖，复用结果签名仍有效的节点，仅从每条依赖路径最早的失效节点继续执行。
- 待更新的旧结果允许查看、对比和撤销，但不能静默参与当前交付；失败时停止依赖该结果的后续节点。
- 自动执行遇到未完成的素材输入、人工编辑或外部处理节点时暂停，等待用户完成并确认；不得跳过、伪造外部进度或自动采用旧结果。
- 旧输出不能静默冒充当前结果，失败不能静默回退到测试页面或旧链路。
- 整理和抠图不强制先后；整理节点保持输入帧集的原图或透明类型。
- 引擎预览和导出始终是可重新生成的派生结果。

## R6-A 实施边界

R6-A先建立产品骨架，不直接搬运旧页面：

1. 定义可版本化的工作流项目格式。
2. 定义第一版九类功能节点和七类资产（两类视频入口已合并）。
3. 定义素材输入、本地自动、人工编辑和外部处理四种执行模式及暂停/继续语义。
4. 定义强类型端口、多输入数量约束和有向无环校验。
5. 定义节点运行状态、输入/参数修订和下游待更新传播。
6. 定义结果签名、有效结果复用、最早失效节点续跑和失败分支停止规则。
7. 定义黑灰白视觉令牌、状态色边界和节点/检查器/弹窗的基础层级。
8. 为后续接入现有算法预留适配接口，但不复制旧页面业务逻辑。

退出条件是协议样例和连接校验测试通过；不能把协议完成写成可用产品。

R6-A实现落点为`app/workflow_schema.py`，生成Schema为`docs/schemas/workflow-project-v1.schema.json`，可回读样例为`docs/examples/workflow-project-v1.valid.json`。项目允许保存不完整草稿；运行前检查负责报告缺输入、缺参数和等待操作，非法连接在保存校验阶段直接拒绝。结果签名计算、待更新传播和真正执行仍属于R6-C。

## R6-C1 参考图输入切片

- 节点内点击或拖入单张 PNG/JPG/WebP；上限20 MB、4000万像素，预览完整显示而不裁切。右侧可以查看、更换。
- `web/workflow-image-store.js`用浏览器IndexedDB保存不可变原文件、文件名与尺寸；现有本机草稿仅保存`AssetRevision`和`NodeResult`引用。刷新可恢复，不承诺跨浏览器或清理站点数据后恢复；尚无项目文件导出/服务端备份。
- 素材库写事务完成后才保存清单，清单成功后才切换当前图。取消、解码失败、存储失败保留原引用；缺失原文件明确要求重新导入。异步导入途中删除/清空画布不能复活节点。
- 素材哈希作为当前源结果标识；相同字节换名不影响下游，换内容将可达下游的已有结果`confirmed`设为false。未执行节点不伪造结果；完整执行签名和调度器仍未完成。
- 复制参考图节点共享不可变源素材；换图不改变另一副本。旧素材修订暂保留在浏览器库，清空画布不等于清空站点素材库。
- 验证：Node领域测试、Chrome文件选择/空选择、拖入、损坏文件、存储失败、刷新回读、复制和导入途中删除；截图为`output/acceptance/workflow-reference-import.png`（合成测试图，不是模型效果证据）。
- 存储依据：[IndexedDB官方使用说明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)，使用事务完成事件确认持久化，不把单个请求成功当成事务完成。

## R6-C2 动作视频与状态（2026-10-11）

- 两类视频节点合并为一个素材输入节点，参考图连接可选；旧本机测试草稿保留ID、位置、连接和备注后转换，不丢弃整张图。
- 视频选择/拖入与参考图复用同一素材存储和发布流程，浏览器可解码的MP4/WebM/MOV上限256 MiB。显示实际尺寸和时长，不伪造来源帧率。生成备注默认折叠，不必填写。
- 已有关联视频在参考图、备注或输入连接变化后待更新，独立分支不受影响；旧视频仍可播放。明确确认采用只恢复视频本身，不恢复下游；取消和Escape无修改。
- 状态点与标题区使用同一状态计算：灰色等待、白色导入中、绿色就绪、黄色待更新、红色失败。未接通节点保持灰色，不冒充执行成功。
- 验证：前端48项、Python全量94项通过/1项真实模型条件跳过、Chrome定向13项通过；真实MP4解码与播放、选择取消、刷新恢复、备注失效、画布拖线关联、换参考图失效、采用取消/确认、坏视频保留原文件均覆盖。仅在隔离浏览器上下文验证，未刷新用户页面或重启主服务。
- 边界：文件内容哈希不是完整输入签名；执行器、服务端仓库、抽帧与抠图的画布调用仍待实现。
