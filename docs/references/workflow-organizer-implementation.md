## 状态与保存边界

### 旧版基础操作补齐（2026-10-11）

- 预览支持滚轮缩放、拖动平移、适配和100%实际像素；窗口变化时适配视图重新计算，手动缩放和平移不被重绘覆盖。
- 上一帧/下一帧遍历全部保留帧并在两端停止，与勾选集合独立；没有勾选时仍能查看，但不能播放。
- 预览帧率1–60仅影响工作台播放，不改变原始帧时长或确认输出；默认单次播放到末帧停止，可切换循环，切到后台暂停。
- 恢复原序列使用应用内确认弹窗，取消不改变内容；恢复全部原帧和原始顺序，可一步撤销。拖到时间轴空白处移到末尾，与交换共用原领域历史。
- Ctrl+A全选、Esc取消勾选；输入框编辑与确认弹窗不触发工作台快捷键。
- 定向浏览器3项及领域4项通过，覆盖新操作、真实FFmpeg交接和600帧短屏。8899手动验证取消恢复、恢复撤销、无勾选导航和播放停止；未操作8897工程数据。

### 循环、播放、排序与长序列补齐（2026-10-11）

- 寻找动作循环分析全部保留帧（7–600帧），复用旧算法：逐帧解码到24×24描述，工作线程分析预算45秒。静止或无可靠周期返回空，不自动强凑候选。
- 候选弹窗独立查看、循环预览和切换；取消、关闭、超时和上游签名变化均不提交，工作线程终止并隔离迟到消息。确认候选只替换勾选集合，保留循环外帧，使用既有编辑历史，可一步撤销，随后仍需“确认整理”发布帧集。
- 单次/循环切换与预览帧率不写入资产或改变时长。拖动显示“交换”或“移到末尾”，换序采用位置过渡，减少动态效果设置下禁用动画。
- 时间轴保留轻量帧卡片，但只加载可见范围及邻近240像素的缩略图，最多两路解码，缩小到240×140以内；离屏和关闭释放对象地址。主预览仅保留当前完整图片地址，共享播放器缓存最多32项。输入PNG Blob仍随帧集载入，这不是完整数据分页或DOM虚拟化。

循环检测已接入；抠图精修及导出仍未接入新版工作流。

1. 上游未就绪：工作台入口禁用，旧整理结果保留但待更新。
2. 打开：按工作流、节点身份和上游签名加载草稿；没有草稿时，已确认输出可恢复帧序，否则从上游全部帧开始。
3. 输出勾选集合或顺序变化：先持久化旧结果失效，再保存编辑草稿；查看不改输出，勾选变化纳入撤销历史并使旧输出及相关下游失效。保存失败回滚本次编辑，显式报错，不能把旧输出冒充有效新结果。
4. 确认：至少保留一帧，生成独立帧集和输入/顺序签名，PNG保存完成且上下文仍一致后，持久化确认输出；失败不替换已有输出。相同已确认签名复用结果。
5. 上游变化：工作台停止播放、禁用编辑/确认；返回并重新打开，按新签名加载对应草稿，不把旧草稿自动套到新输入。

节点删除后重建及复制使用新整理实例ID，避免旧草稿身份复用。复制工作流没有复制未确认草稿；可从其已确认输出恢复帧序。草稿、历史和PNG均是当前浏览器IndexedDB数据，图清单使用localStorage；不是磁盘工程备份。不清理未引用素材或旧输入草稿，后续统一做素材垃圾回收。

- `web/loop-worker.js`、`web/loop-core.js`：复用旧检测核心；旧入口接受受限帧URL，新工作流接受PNG Blob，两种输入必须明确且互斥。
- `web/workflow-timeline-thumbnails.js`：可见范围观察、两路解码、缩略图缩小、离屏释放与迟到结果丢弃。
- `web/workflow.js`：复用 `workflow-image-store.js` 的同一IndexedDB；上下文检查、图保存冲突与下游失效。
- `app/workflow_schema.py`：现有整理节点双类型透传协议，不引入第二套注册表。
