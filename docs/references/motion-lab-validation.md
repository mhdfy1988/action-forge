## AI参考图片与视频

- 预览右上角“拍照”保存当前姿势PNG；“录像”从头录制当前预览：源动作、时间轴编排或自定义动作预览。姿势预览有编排时录制该编排，无编排时提示使用拍照。包含动作裁剪、变速、姿势停留和手动过渡，不另建采样路径。
- 输出尺寸保持当前视口比例，适配1920×1080范围并取偶数；视角在开始时固定，背景沿用黑灰/绿幕选择。输出只含模型、灯光和背景，临时隐藏网格/骨架/变换工具后，在独立WebGL渲染器按目标尺寸绘制3D，再等尺寸复制到编码画布，无缩放或预览截图拷贝，立即恢复辅助物可见性；HTML控件不进入画布。
- 录制锁定模型、素材、编排、相机与背景，停止按钮保持可用；自动播完或点击停止后下载，并恢复开始前姿势、播放状态、控件及原inert状态。暂停在后台或离页时取消，不下载不完整失败结果。无音频，不请求摄像头/麦克风/屏幕权限，不自动上传AI。
- reference-capture.js只封装浏览器编码及下载，motion.js负责现有采样/场景适配。先检查isTypeSupported，再用同尺寸短片预检实际字节，选择可用MP4/H.264或WebM/VP9；状态区明确显示格式，失败不把WebM改名MP4。正式录制若空文件/编码失败，显式报错、恢复编辑，不自动重录；超过300秒或128MiB拒绝。
- 30fps为实时捕获目标，使用captureStream(0)与requestFrame在绘制后取帧；源时间按墙钟时间及所选播放速度采样。编码目标24Mbps（浏览器实际平均码率随内容变化），禁用VP8降级。受设备负载影响，不保证离线恒定帧率。视频是参考素材，不是导出的骨架动画或磁盘工程。
- 源码与依据：[captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream)、[requestFrame](https://developer.mozilla.org/en-US/docs/Web/API/CanvasCaptureMediaStreamTrack/requestFrame)、[MediaRecorder支持检查](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)。MDN明确支持标记不保证编码一定成功。隔离Chrome发现首个MP4实例及显式低级别配置可能返回0字节，故采用实际预检和明确格式选择，而非反复试错或静默重录。

## 边界

- 时间轴片段宽度按真实时长比例分配，进度条有效行程、刻度和播放线共用坐标。长编排在同一容器内横向滚动，播放越过可视边界才跟随；短过渡使用简短标签，悬浮显示完整名称及时间范围。

- 加载器解析网格、骨骼、蒙皮与内置动画；动画混合器逐帧更新模型姿态，不由AI生成动作。
- 追加动作要求骨骼名称、父子关系及初始局部变换匹配；仅支持位置、旋转、缩放轨道。名称相同不代表任意骨架兼容，不自动重定向。
- 已提供动作/姿势编排时间轴，但不提供根运动对齐、脚底锁定、关节约束、武器挂接、视频输出或磁盘工程导出。姿势是骨骼局部变换，不是从2D图片自动识别。
- 单次文件总量最多256 MiB，拒绝模型引用远程资源；贴图重名须先整理。
- 错误导入显式提示，并保留此前成功载入的模型。
- 手脚拖动使用逆向运动学（IK）：只旋转关节，不修改骨长。鼠标沿当前相机平面移动，过远目标停在可达边界；内置已核对四肢链增加最大屈曲与方向目标，未知外部链不套人体限制。无全身重心、碰撞或肩髋完整生理限位。识别Quaternius、Mixamo及明确Left/Right Hand/Foot名称的同层级四肢；未知或歧义骨架不显示可用拖柄。
- 拖动可用Esc/指针取消回滚；提供上次拖动撤销和初始姿势恢复。播放时隐藏拖柄，避免动画覆盖编辑。保存姿势仍复用既有快照和时间轴。

### 画质修正与证据

- 旧1280×720边界下的预览缩放会丢失细节，旧格式列表还允许降到VP8；本轮删除这两条路径，不保留静默回退。保持相机/色彩输出与视角比例，高清渲染器只在拍照/录像期间存在，结束释放GPU资源，不影响主预览尺寸。
- 源码依据：Three.js WebGLRenderer.setSize/setPixelRatio配置真实绘制像素，dispose释放GPU资源（[官方文档](https://threejs.org/docs/pages/WebGLRenderer.html)）。ReferenceCapture使用24Mbps目标，不把目标值写成实测平均码率（[MediaRecorder码率说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/videoBitsPerSecond)）。
- reference-quality.spec.js将预览窗口缩小，核对实际PNG/视频仍为1920像素宽；以固定姿势PNG对照真实视频首帧，只裁人物包围区域做SSIM，而非靠纯色背景提高分数。统一像素格式/色彩范围及时间基后分别检查RGB和亮度结构；视频4:2:0不宣称无损。门禁RGB>0.94、亮度结构>0.98。本轮H.264样本人物RGB SSIM=0.950619、亮度结构SSIM=0.990347，证据写入output/acceptance/reference-quality.json。
- 尝试收口：仅提高输出尺寸和码率不足以覆盖编码降级；直接WebGL取帧/颜色对照还暴露YUV与PNG比较口径差异。最终使用独立高清3D渲染＋等像素编码适配＋H.264/VP9预检，移除VP8，并用人物区域的正确色彩与亮度指标验收。实时录制边界不变，不冒称离线逐帧电影导出。
