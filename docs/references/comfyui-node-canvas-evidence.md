## 源码证据

### 可编辑工作流与执行图分离

- `script_examples/basic_api_example.py:4-95`：API执行图以节点ID为键；每个节点只保留`class_type`和`inputs`。常量直接写入`inputs`，连接写成`[上游节点ID, 输出槽索引]`。
- `server.py:1138-1206`：`POST /prompt`接收执行图，先调用`validate_prompt`，通过后才进入执行队列。
- `server.py:1186-1191`：工作流元数据单独处理，不属于节点执行所需核心输入。
- 本项目落点：项目保存“编辑图”，包含位置、尺寸、分组和视口；运行前编译成不含界面布局的“执行图”。执行器不得依赖画布坐标或选中状态。

### 节点协议由节点类型声明

- `nodes.py:1255-1275`：节点通过`INPUT_TYPES`声明必填输入及参数约束，通过`RETURN_TYPES`声明输出，通过`FUNCTION`指定执行函数。
- `nodes.py:1669-1728`：输出节点额外声明`OUTPUT_NODE = True`，并可以同时返回运行结果和界面预览信息。
- `server.py:818-826`：后端把节点声明转换为前端可消费的输入、输出和列表信息。
- 本项目落点：建立统一节点注册表，由节点定义声明端口、参数Schema、执行适配器和是否为输出节点；检查器由Schema生成基础表单，复杂编辑器仍显式实现。

### 连接、类型与环校验

- `execution.py:848-970`：验证从节点输入递归沿连接向上游检查；缺少必填输入、连接格式错误、返回类型不匹配和依赖成环均产生结构化错误。
- `execution.py:929-960`：连接必须是长度为2的`[node_id, slot_index]`，并用上游`RETURN_TYPES`与下游输入类型核对。
- `comfy_execution/graph.py:288-316`：运行阶段没有可执行节点时再次检测依赖环并显式失败。
- 本项目落点：保存时和运行前均校验；连接使用稳定端口名而不是槽索引，避免节点增加输出后旧项目错位；第一版只允许有向无环图。

### 从输出节点反向构建执行范围

- `execution.py:1146-1192`：执行入口先寻找`OUTPUT_NODE`；没有输出节点的提示图不可执行。
- `execution.py:1204-1213`：只从目标输出递归验证其依赖。
- `execution.py:732-799`：执行器把目标输出加入`ExecutionList`，再按依赖就绪情况逐个调度。
- 本项目落点：允许画布保留未连接草稿；运行“导出”“游戏预览”或用户指定节点时，只编译并执行该目标的上游闭包，不要求整张画布全部完成。

### 拓扑执行与结果复用

- `comfy_execution/graph.py:117-181`：`TopologicalSort`记录阻塞计数和依赖关系，只有上游完成的节点才进入就绪集合。
- `comfy_execution/graph.py:217-264`：`ExecutionList`把输出缓存纳入依赖调度，已缓存上游可以直接供下游使用。
- `comfy_execution/caching.py:83-149`：缓存签名包含节点类型、本节点参数、连接关系及有序上游祖先签名。
- `execution.py:65-106`：节点可以提供`IS_CHANGED`或`fingerprint_inputs`补充外部输入变化指纹。
- 本项目落点：节点输出修订由节点类型、参数、上游资产修订和外部文件指纹共同决定；未变化节点可复用结果，变化节点及相关下游显示“待更新”。动作工坊输出是持久资产，不能只依赖内存缓存。

### 动态子图属于后续能力

- `comfy_execution/graph.py:23-73`：`DynamicPrompt`可以在执行时覆盖原节点并加入临时节点。
- `execution.py:590-614`：节点运行时可以返回扩展图，执行器把临时节点和新输出加入当前调度。
- 本项目落点：第一版不实现运行时动态扩图。动作分支和专注工作区先使用静态节点图与显式资产修订，避免执行模型过早复杂化。

## 官方资料

### 工作流、节点与连线

- 来源：[ComfyUI Workflows: Nodes, Links, and Visual Programming](https://docs.comfy.org/basic-concepts/workflow)
- 核心行为：工作流是连接节点形成的图；节点执行具体步骤；连线把上游输出传给下游输入；工作流可保存为JSON。
- 本项目落点：画布是可执行、可保存的产品工作流；节点定义为功能实例，资产通过连线流动。

### 属性与强类型端口

- 来源：[Properties](https://docs.comfy.org/basic-concepts/properties)
- 核心行为：节点属性既可以由界面控件填写，也可以由输入端口驱动；不同数据类型不能混接。
- 本项目落点：节点轻量参数由检查器编辑，资产端口使用`ReferenceImage`、`ActionVideo`、`FrameSet<T>`、`ActionClip`等强类型；非法连接在交互阶段阻止。

### 连线可视化

- 来源：[ComfyUI Links: How Node Connections Work](https://docs.comfy.org/basic-concepts/links)
- 核心行为：连线表示数据流，端口和连线按数据类型区分，只允许兼容类型连接。
- 本项目落点：拖线时只高亮兼容端口；空白处松开只显示可接收当前类型的节点；非法端口显示具体原因。

### 子图与深层编辑

- 来源：[子图功能](https://docs.comfy.org/zh/interface/features/subgraph)
- 核心行为：复杂节点组合可以封装成可复用子图；子图暴露受类型验证的输入输出，并支持进入内部编辑后返回父级。
- 本项目落点：第一版不实现通用子图系统，但保留“节点进入专注工作区、返回原画布上下文”的交互；未来动作分支可评估封装为可复用子图。

### 节点渲染实现选择

- 来源：[Nodes 2.0](https://docs.comfy.org/zh/interface/nodes-2)
- 核心行为：ComfyUI从纯Canvas节点渲染转向基于Vue的节点系统，以支持更丰富的组件和更快的界面迭代，同时仍需关注复杂工作流性能。
- 本项目落点：暂不因“像ComfyUI”就预设渲染技术；R6-B选型时必须同时验证节点内表单交互、缩放性能和复杂图规模。

## 明确不照搬的内容

- 不把底层算法参数全部暴露为节点，第一版使用游戏资产领域节点。
- 不在第一版开放任意自定义节点、脚本节点和循环图。
- 不把帧排序、精修和跨动作校准压缩进狭小节点卡片，复杂编辑进入节点专注工作区。
- 不用节点图掩盖项目保存、资产修订和下游待更新传播；这些是动作工坊必须自行建立的领域能力。
