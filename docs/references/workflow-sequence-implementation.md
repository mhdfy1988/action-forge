# 序列帧处理：合并入口与实现索引

更新时间：2026-10-11。当前新建流程以本文为准，旧抽帧和整理索引保留历史及兼容证据。

## 输入、输出与状态

一个“来源”端口，最多一个连接，接受动作视频、源序列帧或透明序列帧。视频先设置起止范围与采样率，再抽取真实PNG；帧集直接进入整理，隐藏抽帧设置。确认仅输出勾选帧，按当前时间轴顺序排列，源帧保持源类型，透明帧保持透明类型。未勾选帧仍留在时间轴，可以继续补勾；零勾选时禁止确认。

首次：连接视频 → 抽取 → 未确认整理 → 编辑/循环检查 → 确认 → 下游可用。修改输出勾选集合、顺序或上游输入/抽帧参数后，已有输出待更新。参数未变化时复用原始帧，不重置编辑。重新抽取先确认；成功切换到新的未确认原始帧集，取消和失败保留旧整理草稿。原始帧、整理草稿、确认输出分开保存；刷新不能把自己的确认输出当作原始输入。

## 布局与操作

- 全局工程/工作流导航保留，工作台仅覆盖画布。
- 工作台顶部名称在左，状态及“返回画布”在右；与透明背景、旧抽帧/整理入口一致，返回保留画布视野及选择。
- 中间主预览切原视频/序列帧，播放、前后帧、缩放等使用既有图标系统。
- 右栏随页签切换：原视频为“抽帧设置”，显示来源视频名，底部仅抽取按钮及预计帧数；序列帧为“输出设置”，展示输出帧数、图片尺寸和PNG格式，底部仅确认按钮，不显示视频名、输出帧率或输出时长。播放器下方的预览帧率仅控制预览，不修改帧数据中的来源时间或时长；后续动作节点负责动画播放参数。移除逐帧恢复列表，显式删除可撤销或重置。
- 桌面骨架填满工作区，设置栏272px贴右、底部时间轴固定220px；只限制内部预览画面与控制组最大760px，不在网格两侧添加空列，也不让时间轴撑满剩余高度。原图不强制放大，播放控制紧跟画面。100%时不重复显示缩放读数。短屏三项参数与提交按钮全部可达。
- 底部横向时间轴，编辑工具集中在时间轴上方：撤销、恢复、重置、循环检测、全选、全不选、删除。
- 抽取范围归属右侧处理设置：开始/结束时间并排，下面是紧凑双端滑杆，端点标注零时刻与视频总时长，选取段使用冰蓝色。抽帧参数及范围轨道仅在原视频模式显示；结果模式隐藏这些设置，展示图片输出信息，不混列原始预计帧数或视频时长。底部只保留帧编辑时间轴，不再放抽取范围。滑杆与时间输入双向同步，拖动定位原视频；短屏设置可内部滚动，底部确认可达。单帧删除按钮在悬浮或键盘聚焦时显示，触屏保留可见。
- 勾选框常驻时间栏左侧，勾选帧使用浅蓝灰底，未勾选帧缩略图弱化；当前查看独立使用蓝色边框及竖线。勾选数量放在整组操作之后，不夹在循环与选择按钮之间。不能为了简洁隐藏选择状态。
- 时间轴编辑工具和播放器使用固定Lucide图标，保留中文悬浮提示与无障碍名称。返回画布、打开工作台、抽取、确认输出和弹窗确认/取消使用文字按钮；适配、100%及播放模式保留文字。右栏工作台入口使用中性按钮，确认输出才使用冰蓝主按钮，不能将业务操作全部图标化。

## 源码落点

- `app/workflow_schema.py`：`process-frames` 协议及输出类型透传。生成JSON Schema与前端节点目录。
- `web/workflow-core.js`：连接约束、失效传播及稳定实例身份。
- `web/workflow-sequence-workbench.js`：组合工作台、视频预览、参数、范围、重抽确认。
- `web/workflow-organize-workbench.js`：复用编辑器、历史、预览和循环入口，提供组合生命周期钩子。
- `web/workflow-extraction.js` / `web/workflow-organizer.js`：输入适配及确认帧集，不复制FFmpeg或帧编辑算法。
- `web/workflow.js`：原始帧引用、输入签名、草稿/确认输出、异步迟到隔离；原始引用写入后取消或清单保存失败时恢复旧引用。
- `web/workflow-timeline-thumbnails.js`：可见范围加载、两并发、离屏释放，未加载图片不显示破图。

## 兼容与边界

旧 `extract-frames` 和 `organize-frames` 节点仍有明确工作台入口，保持原画布、资产和连线；新建菜单只提供合并节点。注册表含10种定义，其中2种是旧拆分兼容定义；样例同时保留旧链路与一条合并分支作为协议对照，不代表推荐新建两套流程。没有静默回退、没有自动破坏性迁移。

主入口仍为原浏览器的8897；8899仅隔离验收。帧素材、原始引用和草稿存在IndexedDB，画布清单在localStorage，不是磁盘工程备份。抠图和导出尚未接入此工作台。本轮未提交、未推送、未发布。
