# 关节拖动试用版与源码证据

2026-10-12，Three.js r186，独立8900静态入口；未提交、推送或发布。

## 操作与边界

手脚拖目标位置；肘膝方形点拖弯曲方向；骨盆方形点直接平移；头、脖子、肩、胸、腰等圆形点点击旋转。BodyControls原15个点复用，没有新增关节覆盖层或面板。拖动沿相机平面，深度方向可换视角调整。保存、取消和撤销沿用原链路，默认姿势只编辑副本。

`pose-ik.js`只对已核对的lowerarm→upperarm、calf→thigh与DEF等价链启用两骨限幅求解。以手势起始姿势、两段长度计算末端可达距离和弯曲平面，肘155°/膝160°最大屈曲；只修改四肢旋转，局部位置、缩放和骨长不变。其他明确外部链保留显式无人体限制的CCDIK路径，不是错误捕获后的静默回退。

肘膝方向拖动保持已弯曲末端位置和世界朝向。直肢没有唯一弯曲平面，首次方向拖动设置35°轻弯，末端回收约5%以内；不宣称严格锁脚。手脚目标拖动维持当前弯曲面，直肢按模型前向校准（腿向前、肘向后）。骨盆带身体移动，不锁手脚。没有全身平衡、穿插检测、肩髋完整生理限位；数值微调、旋转和动画不会被强制修正。

## 源码依据

- [ozz-animation两骨IK示例](https://guillaumeblanc.github.io/ozz-animation/samples/two_bone_ik/)：末端目标与中间关节方向目标分离，仅输出旋转。两段长度固定时，余弦定理决定中间关节距轴的高度，方向目标决定所在平面。
- [Three.js CCDIKSolver](https://threejs.org/docs/pages/CCDIKSolver.html)及安装源码`node_modules/three/examples/jsm/animation/CCDIKSolver.js`：maxAngle限制迭代步长；rotationMin/Max为绝对局部Euler角，不能直接套不同绑定轴。现有接口没有方向目标，故在LimbIK适配层补小型两骨几何求解，无新依赖或动画运行时。
- `pose-drag.js`统一指针捕获、相机平面映射、起始快照、取消和撤销；`body-controls.js`将已有肘膝、骨盆按钮接入同一手势处理器，其他关节仍用TransformControls。

## 验证与接续

本轮构建通过，32项领域测试与53项Chrome完整回归全部通过；8项定向交互测试通过，diff检查通过。试用入口保持8900。

`motion-ik.test.mjs`使用两个真实资源，核对四条链、根旋转/等比缩放、可达范围和最大屈曲、骨骼局部位移/缩放/父节点不变、方向拖动后的末端位置与朝向。GLB float32四元数比较须先归一化；不靠增大角度容差隐藏错误。

`joint-drag.spec.js`在两个人偶中真实拖肘膝、骨盆与手脚，核对视觉位置、旋转保留、撤销/Esc、命名保存和刷新恢复。截图`output/acceptance/joint-drag-quaternius.png`与`joint-drag-mesh2motion.png`。完整验证包括原自由观看、20固定视图、拍照录像和人物区域画质。

本轮发现8900原服务停止后恢复同一入口，使用隔离Chrome验证，不触碰8897及用户工程，不自动刷新用户页面。后续用户试用反馈优先调整交互与方向控制，不扩大到物理全身求解。
