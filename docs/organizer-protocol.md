# M2交接与整理输出v3

M2在既有8897项目中作为独立业务模块，抽帧完成后直接点左侧步骤栏“整理”。固定工作台只切工具，没有进入/返回按钮或外部PNG/ZIP导入。M1 v2导出仍原样，M2不改变原任务；顶部导出位置按当前步骤选择原M1或全部整理保留帧的v3。

## 会话与源帧

### 查看与勾选

界面历史操作统一叫“撤销 / 恢复”；恢复对应内部redo，重新执行刚才撤销的操作，并非直接找回删帧。按钮、Ctrl+Shift+Z和Ctrl+Y共用原redo历史，误删找回使用撤销。下文技术语义中的重做均指该恢复操作。

当前查看帧（`active`）与勾选集合（`selected`）是两种独立状态。交接后查看首帧，但不自动勾选；点击图片、前后查看和播放只改变查看帧。右上角复选框独立勾选／取消，不切换预览，无需Ctrl多选；Shift点击复选框按上次勾选锚点连续勾选。全选／取消勾选不影响当前预览。

帧卡片右下角垃圾桶在悬浮/键盘聚焦时显示，非悬浮触屏常显；点击立即仅删除本帧，无需先勾选、不以当前查看帧或其他勾选集合代替目标。remove([id])和底栏remove()共用commit与历史，不复制业务逻辑、不先改变selected；其他勾选保留，被删帧若勾选则从集合中移除。点击不冒泡到查看、不发起拖动，原视频/源PNG不删除；每次删除一历史步，可撤销/恢复。导出中或会话失效禁用。键盘删除后焦点移到邻近垃圾桶，删空则回撤销按钮。

删除和播放作用于勾选集合。排序直接拖到另一张卡片交换两帧：无需先勾选，全选也只交换这两帧，中间帧不动，不改变查看或勾选。目标显示绿色边框与交换标记；帧区空白处追加到末尾。前移/后移按钮、旧勾选块移动及左右插入入口已移除。桌面Chrome使用既有原生拖放链路，不宣称已实现手机触摸拖拽。

核心swap(id,target)显式交换两个有效身份的位置；append(id)仅供空白落点追加末尾。无效身份、自身交换、已在末尾追加不记历史。排序复用commit、最多100步撤销/重做，稳定身份携带原图片/来源/时长；不复制像素或新增后端协议。取消/拖出后清掉目标标记；工作中、过期或外部文件拖入不触发排序。

卡片始终显示原帧编号sourceIndex+1，删帧或交换后不重新编号；悬浮提示同时给出原编号与当前位置。播放计数仍是勾选序列中的位置/数量，不是原编号。导出PNG文件名按输出顺序连续编号，清单稳定ID保留原来源。不能用原编号代替输出顺序或接口sourceIndex。

编辑前后按稳定ID捕获卡片坐标，用浏览器原生动画从旧位置移动到新位置，持续360毫秒；撤销/重做同样适用。只处理旧位置或新位置靠近可见区的卡片，600帧不全量堆动画；减少动态效果偏好下直接完成排序、不播放位移。动画只影响展示，不延迟状态提交或改变图片/清单。

取消勾选后删除禁用，但拖动仍可用；重置返回原顺序并清空勾选，内容编辑撤销/重做仍恢复对应历史状态。勾选和查看本身不增加编辑历史；导出仍包含当前整理序列全部保留帧，而非只导出勾选帧。蓝框表示查看，绿色白勾表示批量操作对象，不再用装饰性伪元素冒充可点击控件。

### 播放勾选帧

唯一播放入口只播放勾选帧，不提供另一套播放模式；没有勾选时禁用。播放集合由当前整理顺序过滤勾选身份得到，不按勾选先后，不由当前查看帧截断；每次启动从首个勾选帧开始，跳过未勾选帧。播放按钮旁独立设置1–60整数帧/秒，默认12；每张图片显示1/播放帧率秒，不沿用来源时长。播放中调速保留当前帧及帧内进度；非法输入不进入时钟，失焦恢复最后有效值。播放一遍结束后停在最后一个勾选帧；暂停或勾选变化停止播放，再次启动从头开始。

M1原尺寸预览使用同一FramePlayback时钟及帧率范围，但保留既有行为：从当前查看帧开始，结束回到首帧。两个工作区分别记住当前网页中的播放帧率，新抽帧不按采样帧率覆盖播放速度；刷新恢复默认值，不承诺跨刷新持久化。

播放只改变当前查看帧，不改变勾选集合、整理顺序、历史或导出状态。勾选播放不是删除未勾选帧，导出仍包含全部保留帧。手动上一帧／下一帧仍用于查看整个整理列表。

播放区只显示`勾选序列中的当前帧号 / 勾选总数`，勾选变化即时更新。查看未勾选帧时序号为`—`，不伪造播放集合中的位置；无勾选显示`0 / 0`。悬浮提示只保留当前查看帧在保留列表中的序号，右侧“保留”摘要统计全部导出帧。

序列帧界面不显示源时间、当前时间或总时长：包括M1/M2缩略图、结果摘要、原尺寸查看和悬浮提示。来源/时长仍保存在内部清单用于追溯与既有输出；预览帧率不改内部字段、抽帧采样率或导出时长，不增加编辑历史。视频输入侧的截取时间不在移除范围。

`POST /api/edit-sessions`仅接`jobId`，返回编辑会话ID、源任务ID和完整v2快照；未完成/不存在任务失败。会话不把PNG复制到浏览器内存，原尺寸与缩略图复用既有帧接口。

会话将源任务钉住，缓存TTL/容量回收不得删除它。最多3份会话；网页每30秒心跳，未更新超过现有TTL（一小时）后释放，不承诺无限闲置/服务重启恢复。侧栏切抽帧/整理只暂停播放和切工具，不释放/重建编辑会话，保留顺序/勾选/查看/缩放/滚动/历史/速度；没有“结束整理”入口。新抽帧结果与旧会话不同则侧栏显示更新点，接收时若旧编辑未导出则先确认，成功替换后释放旧会话。页面退出也尝试释放，但浏览器强制关闭不能保证pagehide请求送达；此时依TTL释放，不用删除活跃源绕过容量保护。所有结果都被持有而无可回收任务时明确拒绝新抽帧。交接或整理导出期间锁定侧栏和换素材，不引入第二套后端状态。

交接等待中，抽帧/文件更换/重复交接禁用；成功或失败恢复，避免两次交接竞争覆盖工作状态。失败不静默接受上一份结果。

## 输出与时间

循环检测试验版分析全部当前保留帧，输出绑定版本与有序ID的候选[start,endExclusive)。预览不改主序列，确认“只保留这个循环”才复用commit一步裁剪，可撤销恢复；勾选过滤保留而非替换为候选。导出仍包含全部保留帧，不因预览设置循环或改变原时长。边界、45秒预算、至少7帧和已知限制见[循环方案](loop-finder.md)。

`POST /api/edit-sessions/{id}/export`仅接`frameIds`有序列表；1–600帧、身份唯一且必须属于源任务。客户端不能指定时长、来源PTS、路径或额外字段。

输出ZIP包含整理清单与保留帧的原PNG字节。文件名按当前顺序重排，稳定ID/源PTS/采样时间/实际源时间/每帧精确时长保留。删除裁掉帧及时长；排序只改变排列，不改变总时长。没有自动重复合并。

- `formatVersion:3`，新序列ID、名称、画布、来源及loop。
- `originalExtraction`保存原M1抽帧设置，不能把它当整理后区间。
- `derivation`记录父序列ID/版本、原帧数、移除帧ID和保留时长策略。
- `durationSeconds`以Fraction精确求和；`durationMs`供显示。
- `frames`沿用原帧身份与来源，`image`按当前顺序命名；额外`sequenceTimeSeconds/sequenceTimeMs`记录在整理后播放轴的开始位置，不能覆盖sourceTime。

空序列不导出，未变化结果仍导出v3。M3/M4尚未实现，不宣称已兼容；没有v3→v1静默适配。

## 有界输出

M1资源上限不变。M2导出原PNG总量另限256MiB，因浏览器需要下载Blob；同时执行原任务/缓存磁盘预算和120秒预算。不承诺任意4K序列可编辑导出。

使用服务端原帧构造清单，经ZIP成员数、JSON重读、原PNG流式SHA256对照完成后才提供下载。下载期间共用忙状态保护文件，成功/异常/断开都在响应finally清除该次精确临时ZIP并释放；不触及原结果和用户文件。前端导出时冻结内容编辑，失败保留工作状态。
