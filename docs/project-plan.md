# 动作工坊产品总纲

## 文档定位

- 画布已增加帧处理分支的右键自动执行与预设，自动确认后继续、不在精修处暂停；完整调度及后续动作/导出仍未接通，见[自动执行索引](references/workflow-auto-implementation.md)。

- 本文是动作工坊（Action Forge）的整体产品与阶段路线总纲。
- 当前执行指针以[当前任务](stages/current-todo.md)为准；节点、端口、状态和执行细节以[工作流画布与节点模型](workflow-canvas-node-model.md)为准。
- 状态：R6-A/B基础、素材输入、真实抽帧、整理及R6-C5合并序列帧处理、R6-C6透明背景工作台已实现；完整执行内核、动作编排及端到端导出产品流程尚未完成。透明背景复用旧版模型和精修核心，边界见[实现索引](references/workflow-matting-implementation.md)。
- R0至R5是经过验证的技术组件基线，不等于完整产品已经完成，也不存在必须迁移的正式用户历史项目。

## 产品目标

动作工坊面向2D游戏动作资产制作，目标链路是：

```text
角色参考图
    ↓
生成或导入动作视频
    ↓
提取、整理和抠图
    ↓
制作多个动作片段
    ↓
组装统一角色资产
    ↓
游戏引擎预览与导出
```

产品最终解决的不是“导出一组图片”，而是把同一角色的待机、跑步、跳跃、攻击等动作组织成尺寸、原点、节奏和事件一致的可用游戏资产。

## 当前状态

### 已实现并验证的技术基线

- 视频导入、时间范围抽帧和原始帧保存。
- 帧整理、删除、恢复、交换、循环候选和播放检查。
- 批量抠图、局部去绿和单帧人工精修。
- PNG序列、精灵图集和JSON导出。
- 可恢复的多动作角色项目。
- 共享画布、稳定原点、基准帧、动作锚点和整组校准。
- 固定帧率、逐帧时长和动作事件。
- Godot只读实时预览和JavaScript中立资产适配器。

这些能力仍分布在旧单动作页、角色项目页和独立适配器中，只能作为R6复用的领域能力，不能把现有页面拼接称为完整产品。

### 尚未实现

- R6工作流项目仓库与执行器。
- 可保存、可连接、可执行的正式节点画布。
- 从空项目贯通动作生产、角色组装、预览和导出的统一体验。
- 正式写入用户游戏工程。
- 内置图片生成视频服务。
- 桌面安装包和正式发布版本。

## 产品结构

### 工作流画布

画布是产品主界面，也是可保存的编辑图。用户可以创建、删除、复制、移动、连接和运行节点，允许保留未连接草稿和多个动作分支。

### 节点

节点是一个功能实例，不是资产本身。同一张画布可以有多个“生成动作视频”“整理序列帧”或“制作动作片段”节点，分别服务跑步、跳跃和攻击。

### 资产

资产是节点之间流动的强类型数据，包括角色参考图、动作视频、原始帧集、透明帧集、动作片段、角色资产和引擎资产包。

### 右侧检查器

检查器负责当前节点的轻量参数、输入输出、状态和错误，不复制复杂编辑器。

### 专注工作区与弹窗

- 帧整理、动作片段、跨动作校准等连续复杂任务，从节点进入专注工作区。
- 单帧精修、循环候选对比和危险确认等范围明确的任务使用弹窗。
- 返回画布时恢复原来的平移、缩放、选中节点和连线视图。

## 第一版节点

第一版采用代码内置节点注册表：

1. 角色参考图。
2. 动作视频（外部文件导入，可选关联参考图）。
3. 提取序列帧。
4. 整理序列帧。
5. 移除背景。
6. 制作动作片段。
7. 组装角色资产。
8. 游戏预览。
9. 导出游戏资产。

用户可以自由创建、复制、配置和连接这些节点实例；第一版暂不开放自定义节点插件和任意脚本节点。

## 节点执行模式

| 执行模式 | 含义 | 第一版示例 |
| --- | --- | --- |
| 素材输入 `source` | 用户选择或导入文件，建立受管理的资产修订 | 角色参考图、动作视频 |
| 本地自动 `automatic` | 动作工坊直接调用本地适配器产生结果 | 抽帧、抠图、导出 |
| 人工编辑 `interactive` | 用户进入工作区调整并确认结果 | 帧整理、动作片段、角色组装 |
| 外部处理 `external` | 为未来需要交接的外部任务保留 | 当前无内置节点 |

当前视频全部从工具外导入，因此合并为一个“动作视频”素材输入节点。参考图连接与生成备注可选，备注默认折叠，不显示虚假的生成按钮。已关联的参考图或备注发生变化时，已有视频及相关下游待更新；用户重新导入或明确确认采用当前视频后才恢复视频就绪，下游不自动恢复。视频导入、播放、本机恢复与状态点已接通，完整执行器和输入签名仍待实现。

## 连接与执行规则

- 端口必须按资产类型、连接数量和有向无环规则校验。
- 画布保存编辑图；运行目标节点时，只编译该目标及其上游依赖组成的执行图。
- 上游输入、参数或节点实现版本变化后，仅相关下游进入“待更新”，无关分支不受影响。
- 每个结果签名至少包含节点类型与实现版本、参数、上游资产修订和必要的外部文件指纹。
- 运行目标节点时复用签名仍有效且文件存在的结果，从每条依赖路径最早的失效节点继续。
- 遇到尚未完成的素材输入、人工编辑或外部处理节点时暂停，等待用户完成并确认；之后从该节点继续，不从头重跑。
- 节点失败时停止依赖它的后续节点，但不影响无关分支。
- 旧结果可以查看、对比或恢复，不能静默冒充当前结果交付。
- 预览和导出是可重新生成的派生结果，不能反向覆盖项目图、原素材或人工精修结果。

### 第1轮：导入现有视频

```text
动作视频（导入） → 抽帧 → 整理 → 抠图 → 动作片段
```

第一次运行时依次产生结果；再次运行且输入未变化时直接复用。

### 第2轮：外部生成视频

```text
角色参考图 → 动作视频（导入外部生成结果） → 抽帧 → 后续处理
```

用户在工具外生成视频并导入“动作视频”节点。执行器接通后，目标依赖缺少视频或视频待更新时应暂停；用户完成输入后从失效处继续。当前并未实现自动恢复执行。

### 第3轮：修改上游

已关联参考图或生成备注变化后，动作视频及其已有相关下游进入“待更新”。旧视频仍可查看，但必须重新导入或由用户明确确认采用。未关联参考图的独立视频不受其他参考图变化影响。

## 跨动作一致性

目标是同一角色的跑步、跳跃、攻击等动作切换时大小、脚底位置和原点一致，而不是逐帧抹平动作本身的位移。

- 生成阶段：多个动作复用同一角色参考图和基准状态；具体外部服务是否支持首尾参考，在接入时单独核对。
- 加工阶段：使用基准帧和半透明叠图比较动作，必要时只对整组动作应用缩放与偏移。
- 输出阶段：一套角色动作共用画布、原点、目标尺寸和裁剪规则，禁止各动作独立紧裁后再撑满。
- 跳跃、攻击等动作保留自身纵向和横向运动，不逐帧拉回地面或自动居中。
- 明显的角色外观漂移应优先在生成视频阶段识别，不把后续校准当作生成缺陷修复器。

详细字段与边界见[角色动作资产工作台方向](character-asset-workspace.md)。

## 引擎接入边界

```text
动作工坊项目真值
        ↓
项目中立角色资产
        ↓
预览或导出适配器
   ├─ Godot
   └─ JavaScript / 具体2D引擎
```

- 核心模型不依赖Godot或某个JavaScript引擎格式。
- 动作工坊负责编排帧、循环、节奏、共享画布、原点和轻量事件。
- 游戏输入、角色状态机、战斗判定、AI逻辑和复杂动画混合属于游戏引擎。
- “实时预览”和“写入正式游戏工程”是两个明确操作。
- 正式资产写入必须经过完整校验和原子替换，不能让引擎读取半份结果。

## 视觉与交互原则

- 正式页面采用专业、沉稳的深灰基调，少量冰蓝用于主操作、当前选择和输入焦点；普通文字及面板保持中性，状态色保留独立含义。不使用霓虹、发光或花哨渐变。
- 高饱和颜色只用于选中、端口类型、运行中、成功、待更新和失败等必要反馈。
- 不使用花哨渐变、玻璃拟态、大面积品牌色、无意义闪烁或含义不明的自绘图标。
- 节点、检查器和弹窗通过灰阶、细边框和留白建立层级。
- 页面优先显示名称、状态、关键值和操作，不在多处重复同一说明。
- 现有R6原型只验证“从画布打开节点工作区并返回”，不代表正式视觉。

## R6实施路线

| 阶段 | 主要工作 | 退出条件 |
| --- | --- | --- |
| R6-A 工作流协议 | 定义项目格式、节点注册表、资产类型、执行模式、端口、连线、修订和结果签名 | JSON样例可保存回读；缺失输入、类型错误、数量违规和成环均能结构化拒绝 |
| R6-B 画布基础 | 黑灰白界面、平移缩放、创建/删除/复制/移动节点、拖线、断线和检查器 | 刷新后节点位置、参数、视口和连线完整恢复；尚不宣称真实算法已接入 |
| R6-C 执行内核 | 目标依赖闭包、拓扑执行、结果复用、待更新传播、暂停/继续、失败隔离和强制重跑 | 修改任一上游后只有相关下游失效；三类执行场景通过自动化测试 |
| R6-D 首条真实流程 | 通过适配层接入“导入视频 → 抽帧 → 整理 → 抠图 → 动作片段” | 从空项目实际完成一套动作；不复制第二套旧业务逻辑 |
| R6-E 外部生成与多动作 | 参考图、外部生成视频交接、多个动作、共享基准和跨动作校准 | 外部节点可暂停/继续；参考图变化正确传播；多个动作统一画布和原点 |
| R6-F 引擎与导出 | 角色组装、Godot/JavaScript预览、PNG序列、图集和中立资产包 | 同一角色多个动作可被实际运行时消费；预览和导出不改写项目真值 |
| R6-G 产品验收 | 从创建空项目完整人工操作，覆盖取消、失败、保存、刷新、重启和恢复 | 新画布独立完成产品纵向流程后，再决定替换旧入口和发布计划 |

R6-C3完成真实抽帧与本机帧集恢复，R6-C4完成整理工作台、草稿历史与确认输出；这些切片不是通用执行内核。后续为抠图节点；服务端工作流仓库、后续节点和完整增量调度仍未接通。详细任务和完成状态见[当前任务](stages/current-todo.md)，详细阶段设计见[R6可操作工作流画布计划](stages/character-workspace-r6-canvas-plan.md)。

## 第一版不做

- 用户自定义节点插件和任意脚本节点。
- 运行时动态子图、循环图、条件分支和状态机。
- 多人协同编辑和云端项目同步。
- 把底层模型、前景估计和FFmpeg步骤拆成大量算法节点。
- 在动作工坊内实现游戏输入、战斗逻辑和AI。
- 为不存在的正式历史项目建立复杂迁移兼容层。

## 仓库与演进原则

- 不新建第二个产品仓库；`action-forge`是唯一主项目。
- 旧单动作页和角色项目页只作为R0至R5技术验证入口，不决定R6产品结构。
- 已验证能力通过命名明确的适配层进入R6，确实只存在于旧页面的逻辑先抽成无界面核心。
- 禁止复制第二套抽帧、整理、抠图、播放、几何、导出或保存实现。
- 新路径失败时快速显式失败，不静默回退到旧页面或旧算法。
- Godot、JavaScript等目标适配器留在独立目录，不能污染核心领域模型。
