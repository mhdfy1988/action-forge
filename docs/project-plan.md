# 动作工坊方向与后续计划

## 定位

动作工坊（Action Forge）面向2D游戏动作资产制作。目标链路为图片→视频→序列帧→角色动作资产→游戏引擎；当前完成视频之后的单动作处理链路和R1最小多动作角色容器，不把R2校准或R3引擎连接包装成已实现。

## 已实现

抽帧 / 帧处理 / 导出。整理和抠图自由切换，人工精修弹窗实时同步，最终PNG序列或精灵图集及JSON资产包。独立角色工作区可持久化一个角色的多个动作，并从v2/v3/v4旧结果迁入。当前为本机网页，保留客户端单屏布局，不是已发布桌面应用。

## 讨论确认：跨动作一致性（尚未实现）

目标是同一角色的跑步、跳跃、攻击等动作切换时大小和位置一致，不是逐帧修正所有生成缺陷。

- 生成阶段：同一张角色基准图作为各动作视频的首尾参考，统一画布、角色朝向/大小/位置。实际生成服务是否支持首尾输入，接入时单独核对。
- 加工阶段：用首尾对应的基准状态检查；必要时对整组动作应用一次缩放和偏移，保留跳跃/攻击内部运动，不逐帧拉回地面或自动居中。
- 输出阶段：一套角色动作共用画布、裁剪范围、缩放比例和原点。不能各动作独立紧裁后撑满，否则会再次破坏一致性。
- 基准帧用于校准，是否保留在正式动画由动作需要决定；跑步循环不混入起止过渡帧。

例如第一个动作建立角色基准；第二个动作复用同一参考图生成，抽帧后校准整组；第N个动作仍对齐该基准，所有动作一起验证范围和导出。首尾一致不能保证生成模型完全保持角色外观，明显漂移应先在生成视频检查。

## 已确认的演进决策

- 不新建第二个产品仓库；现有 `action-forge` 是唯一主项目，但新版角色工作区采用独立入口、状态容器和模块边界。
- 不在当前全局页面状态上继续堆角色级功能；旧单动作工作台保持稳定，已有核心通过显式适配层复用。
- 不进行一次性推倒重写；新版完成纵向验收后才讨论切换默认入口，旧链路不作为静默失败回退。
- 不先做孤立的引擎导入工具；先建立最小角色资产容器和中立协议，再立即打通 Godot 实时预览纵向切片。
- Godot、JavaScript 适配器保留在仓库内的独立边界，核心模型不依赖任一引擎格式。
- 动作工坊负责编排帧、循环、速度、基准和事件，不接管游戏输入、状态机、战斗或 AI 逻辑。

完整目标模型、状态、不变式和 R0–R5 阶段见[角色动作资产工作台方向](character-asset-workspace.md)。R0协议和R1最小多动作角色容器已完成，当前下一阶段为R2共享画布、稳定原点与跨动作校准；R3才接Godot实时预览。历史准入依据见[R0准入门禁](stages/character-workspace-r0-gate.md)。
