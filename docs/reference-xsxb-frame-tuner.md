| --- | --- | --- |
| `tools/frame_tuner_lite/public/lite.js` | 扫描一个角色的全部可播放动作帧，合并透明像素边界，计算共享画布与稳定原点。 | 跨动作一致性不能只在单次导出里逐帧裁剪，应由“角色资产”持有共享画布和原点。 |

## 实际界面流程核对

使用动作工坊现有透明帧建立了仅用于验证的 `action-forge-review` 项目，包含 `run` 与 `jump` 两个动作，共 24 帧。

1. 选择项目、角色和动作。
2. 在角色级、动作级或单帧级调整缩放、旋转、偏移和时长。
3. 播放当前动作并逐帧检查；动作拥有独立帧率和总时长。
4. 可选编辑攻击拖尾和受击框、攻击框、碰撞体。
5. 计算全角色统一画布；当前样本得到 `847 × 714 px`，覆盖 2 个动作。
6. 导出 PNG 序列或 Sheet + JSON 到用户选择的本地目录。

实测还确认：动作级参数会独立持久化；切换 `run` 与 `jump` 后不会互相覆盖。碰撞框入口会按透明内容自动生成初始框，而非只有显示开关。

## 验证证据

- `npm.cmd run validate:lite`：1 个角色、2 个动作、24 帧，`warnings: []`。
- `npm.cmd test`：`XSXB self-tests passed.`
- 浏览器导出已进入系统目录选择器；内置浏览器无法接管该系统窗口，因此本次没有把“人工选目录后的落盘”记为已实测完成。

## 动作工坊采用边界

### 第一版采用

- 角色资产容器：一个角色包含多个动作。
- 共享画布、稳定原点和角色基准帧。
- 角色级、动作级校准；播放切换对比。
- PNG 序列与 Sheet + JSON 共用一套中立元数据。
- 导出前验证和导出后回读。

### 后续增强

- 单帧变换覆盖。
- 碰撞框自动初值与逐帧修正。
- Godot、JavaScript 引擎适配器。
- 攻击拖尾与附加图层烘焙。

### 不直接照搬

- 不照搬参考项目的长页面和高密度参数面板。
- 不把拖尾、碰撞框、场景、音频等高级能力同时塞进第一版主流程。
- 不直接依赖参考仓库运行时格式；动作工坊先稳定自己的项目中立协议。
