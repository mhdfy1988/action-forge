3D预览右上角提供“拍照”“录像”：拍照下载当前姿势PNG；录像从头录制当前预览动作/编排，自动结束或提前停止，下载MP4或WebM（编码预检后明确显示格式）。输出只含人偶和当前背景，不含界面、网格、骨架辅助线；保留当前视角和播放速度，不修改编排。用于人工上传给AI作参考，不自动调用AI服务。高清输出在1920×1080范围内保留视口比例，按目标分辨率独立渲染3D，不受预览窗口像素大小限制；视频编码目标24Mbps，支持H.264/VP9，禁用低保真VP8降级。

默认简版支持中英文动作搜索，已识别的内置动作显示中文名，悬浮查看原始名；未知外部名称保留原样。播放器显示源动作/当前编排/自定义动作/姿势，录像提示跟随上下文。初始取景约65%高度；“适合视图”按当前源动作、编排/自定义预览的整段采样范围（姿势模式仅当前姿势）一次拟合，播放中不追随或缩放。素材行高收紧，时间轴源动作与左侧同名显示，原名仅在提示中保留；用户命名不翻译。空时间轴收起裁剪、选择、删除工具，撤销/重做仍保留。

视角菜单提供自由透视编辑，以及正交平视八向（正面、背面、左右侧与四个斜向）、45°斜俯视八向、等角四向。横版2D使用原有“横版侧视 · 向右/向左”；俯视游戏选择斜俯视，等角游戏选择等角。固定视图不旋转，同一组方向共用取景尺度；可缩放和平移，拍照、录像复制当前视角，文件名标注方向。先检查整段最大幅度不出画再录像，根位移不自动追随。当前按方向分别输出，不批量录制或合成多视图。高级验证入口维持原始名称和原取景。

默认界面采用黑灰白蓝极简视觉，蓝色仅用于重点操作和选择状态；素材库、播放器及时间轴统一控件尺寸，保留现有编排操作，高级辅助工具布局不变。

默认动作及默认姿势不可删除，默认姿势身份不可覆盖；默认姿势可编辑副本，同名另存只写自定义姿势。自定义素材每行右侧垃圾桶在悬浮或键盘聚焦时显示，默认素材不显示；无素材右键菜单。点击垃圾桶或按Delete后出现站内确认，取消、关闭或Esc不改数据。删除、同名覆盖、清空和模型切换均使用黑灰蓝站内确认，默认聚焦取消。已放入时间轴的独立片段保留，素材删除不进入编排撤销历史。

保存的自定义动作拖入后是一个整体片段，保留素材名称；拖入空轴时编排标题也带入名称。内部动作、姿势及过渡不烘焙，沿用原采样，整体可裁剪、变速、分割和再次保存；素材库不再提供重新展开内部编排入口。含整体片段的保存格式为版本2，兼容读取旧版本1素材，但旧程序不能读取新合并记录。[交互与保存说明](docs/references/motion-library-interactions.md)。

刷新只恢复上次模型和素材库，时间轴保持空白，不自动打开最后保存的动作。已保存的动作和姿势仍在库中，拖入后再开始编排；未保存的编排不跨刷新恢复。

时间轴边缘命中区向片段内扩展至20像素，短片段自动收紧，悬浮显示握柄。选中动作后工具栏提供“裁剪/变速”切换，拖动边缘跟随当前模式；默认裁剪，Alt可临时变速。变速保留源范围并调整播放速度，姿势和过渡直接拖动右边缘调整持续时间；支持Esc取消及撤销/重做。秒数仅展示，不再提供数值输入按钮或浮层。

从视频素材到 2D 游戏动作资产的本机工作台。

独立 [3D 动作编排验证页](docs/references/motion-lab-validation.md)：8900默认提供简版。顶部下拉菜单按来源切换内置及已导入模型，菜单内提供“导入模型…”；未载入时可直接导入或载入Quaternius人偶；载入后为左侧动作库、中间预览、底部时间轴，无常驻右栏。支持GLB/glTF、FBX，骨骼与绿幕开关保留在预览右上角。可保存多个模型，当前只编辑一个模型的一条动作编排，不接入主工作流或工程数据。

内置模型分为Quaternius与Mesh2Motion：Quaternius为原默认人偶，53骨骼、117动作（原46＋动作库②标准版43＋根位移版本28），合并MakeHuman Community的99姿势（Cinevva整理）；Mesh2Motion为白色人偶，66骨骼、162动作（基础87＋附加75），16个默认姿势从附加动作提取。两者分别管理素材及自定义内容，切换有未保存编排时确认。经固定来源、明确骨架处理与作者轨道规则接入，不放宽外部骨架兼容检查。模型下各库按内容身份隔离；旧65骨骼测试人偶只按内置身份定向清理，其他模型及库保留。首次准备还需运行`node scripts/prepare-motion-candidates.mjs --library-one`下载第一套免费包；来源与其他准备命令见资源扩充说明。

时间轴支持单选、Ctrl增减选择、Shift连续选择、全选及批量删除。拖动片段浮起跟随鼠标，中间交换、边缘插入；多选可成组移动或交换同数量片段。默认拉动作两端裁剪，速度不变；也可在播放头处分割、裁左或裁右。Alt拉边缘单独变速，姿势/过渡拉边缘调整时长；Esc取消。添加、删除、排序、交换、裁剪及变速支持撤销/重做（100步）。全选/全不选用文字，其余编辑工具用统一图标；仅保留预览下方一个播放按钮。重新播放遵循当前上下文：姿势预览有编排则从轴首播放，无编排保持姿势；源动作、自定义预览各自从头播放。

从左侧动作库直接拖入时间轴；单击仅预览，轴外松开或Esc取消不添加。动作默认直接衔接；过渡卡片拖到两段之间才建立，连接前段末帧与后段首帧。素材库上层只有动作库/姿势库两个Tab；动作库内分默认、第三方和自定义折叠组，外部追加动作归第三方组；模型切换位于页面顶部下拉菜单，导入同骨架动作位于左侧动作库标题旁。时间轴“保存动作”命名保存完整编排，自定义条目单击预览、拖入复用、双击编辑。模型文件、源动画及编排在当前浏览器IndexedDB中事务保存，刷新恢复最后保存的模型与动作；未保存编排修改及撤销历史不恢复，不是磁盘工程备份。姿势编辑也可在简版按需打开；模型信息及挥剑模板保留在显式高级验证入口`/labs/motion/index.html?tools=1`，共用同一编排核心，不自动回退。

姿势库分默认姿势库与自定义姿势库。简版“编辑姿势”“保存姿势”位于3D视口浮动工具条，不放在播放器；双击姿势或点击编辑后，手脚拖动目标位置，肘膝方形点拖动调整弯曲方向，骨盆方形点拖动身体位置；头、肩、胸、腰等圆形点点击后用旋转环。支持撤销与取消。微调浮层默认隐藏，只点“微调”才显示；浮层只留一个关节选择、三行角度与关闭按钮，已识别部位显示中文，不重复身体部位选择；已保存姿势与添加片段统一走左侧素材库拖放，不重复提供入口。Quaternius和Mesh2Motion均支持四条手脚链与15个身体控制点。两人偶的四肢拖动保持骨长，肘膝最大屈曲分别155°/160°；直肢拖肘膝时轻弯35°、末端小幅回收，已弯曲时保持手脚位置和朝向。不含全身平衡或身体碰撞。编辑只调整当前人偶，不修改源条目；保存只写自定义组，同名覆盖只匹配自定义条目并确认。姿势库：拖动预览进度定位动作中的任意时刻，点击“保存姿势”命名入库。姿势单击预览、拖入时间轴默认停留1秒，拉边缘调整时长；与动作共用手动过渡、排序、删除、撤销及自定义动作保存。姿势按当前模型隔离，独立保存后也可刷新恢复；已支持同骨架固定姿势GLB/FBX导入；不支持.blend或跨骨架转换。

导入入口随Tab切换：“动作库”下导入动作，“姿势库”下导入姿势。姿势导入只接受同骨架单帧或固定姿势动画，连续动作须先导入动作再定位提取；无动画的静态模型不自动当作姿势。第三方动作和导入姿势均事务保存并支持刷新恢复。

处理节点右键可“自动执行”，各自预设只在右栏设置：序列帧节点配置抽帧与循环，抠图节点配置背景清理（默认容差80）；运行时逐节点读取，不共用全局预设。序列帧与透明背景工作台入口位于右栏底部；抠图参数单列对齐，仅指定颜色时显示背景色，关闭清理时收起相关参数。确认后继续已接通分支，精修可事后进入；画布仍可缩放、平移与查看。缺视频禁用，已有编辑需确认覆盖；动作/导出节点尚未接通。见[自动执行说明](docs/references/workflow-auto-implementation.md)。

## 使用

工作流主入口顶部提供“工程 / 工作流”切换：一个工程可包含多张独立画布，支持搜索、新建、重命名、复制与删除确认。切换前立即保存当前画布；清空只清当前工作流内容。已有单画布草稿首次打开时纳入默认工程，不放入示例数据。目录和画布仍保存在当前浏览器，素材保存在 IndexedDB；不是服务端工程文件，不支持跨浏览器同步。复制画布复用素材引用，删除画布不删除共享素材原文件。多页面同时修改出现冲突时明确提示刷新，不覆盖另一页保存内容。保存路径与验证边界见[工作流工程目录](docs/workflow-project-library.md)。

所有节点使用独立名称，默认如“动作视频 1”，显示在卡片上方；双击名称修改，Enter或失焦保存，Escape取消。改名不改变节点类型或结果有效性，刷新后保留。右侧显示当前名称与固定类型，卡片不重复展示标题和协议计数。

从输出端口拖线，靠近兼容输入端口32屏幕像素内会自动吸附并冰蓝高亮，松手连接；移开释放，Esc取消。不兼容、已满、重复和成环的连接不参与吸附，缩放不改变操作容差。各工作台顶部统一左侧名称、右侧状态及“返回画布”，返回保留画布视野与选择。

工作流右栏只显示当前节点必要配置，不展示内部协议字段。参考图右侧使用紧凑素材卡：完整缩略预览、分行文件名和尺寸、更换图片；点击预览查看原图。序列帧处理和透明背景节点已接通专注工作台；动作片段、角色组装、引擎预览和导出仍待接入画布。

整理预览支持滚轮缩放、拖动平移、适配和100%，单次/循环及独立预览帧率只影响预览，不改变输出时长。前后查看遍历全部保留帧；拖动显示交换或移到末尾的落点，排序带位置过渡。恢复原序列需应用内确认、可取消和撤销；Ctrl+A全选、Esc取消勾选。寻找动作循环分析全部保留帧，提供候选独立预览，勾选候选循环可一步撤销，不删除循环外帧；没有可靠循环不强凑。时间轴缩略图按可见范围预取并释放离屏图片。

- 新工作流画布：打开 `http://127.0.0.1:8897/workflow`。动作视频连接“序列帧处理”，在同一工作台完成抽取、整理与循环检查；也可直接连接已有源帧集或透明帧集。原视频/序列帧切换主预览，右侧设置，底部通栏时间轴及图标编辑工具。抽取成功后可立即编辑，确认后仅输出勾选帧，按时间轴当前顺序排列；未勾选帧仍可继续补勾。重新抽取需确认，取消/失败保留旧草稿。旧画布中的抽帧、整理节点继续读取，不自动改线，新建目录只提供合并节点。详细规则见[序列帧处理](docs/references/workflow-sequence-implementation.md)。草稿、历史和帧集保存在当前浏览器IndexedDB；清理站点数据会丢失，尚无磁盘工程备份。透明背景可接在已确认的原始帧集之后，导出仍未接入此画布。

抽帧工作台保留顶部工程/工作流导航，仅覆盖画布；单主预览可切换原视频与抽帧结果，右侧开始、结束、采样率采用三行可编辑数值。底部通栏时间轴支持缩略图尺寸、选帧与播放跟随；共享范围轨道的起止手柄定位原视频。主操作、当前标签页和选中帧用少量冰蓝强调，面板保持深灰。清空当前画布位于画布空白处右键菜单，仍需应用内确认。

透明背景工作台已接入新画布：将已确认的原始帧集连接“移除背景”，打开工作台后去除背景；支持补抠、取消、重新处理确认、逐帧/循环播放和双击精修。未处理时直接查看原始帧；当前帧已有结果后才提供原始/处理后滑动对比，不再设置切换页签。检查背景使用预览区右下角色块，缩放在左、播放居中；双击画面或时间轴帧进入精修，不设独立精修按钮。精修沿用移动、擦除/恢复画笔、魔法棒、选区、撤销/恢复/重置、缩放与背景检查，主题统一深灰与冰蓝；右上角X关闭前等待像素和本机保存完成，失败留窗重试。全部帧处理完成且任务结束后才显示确认输出，发布独立透明PNG帧集，原图不覆盖，顺序与逐帧时长保留。完整能力核对及边界见[透明背景实现索引](docs/references/workflow-matting-implementation.md)。

### 旧技术验证入口

以下能力属于旧 `/` 单动作页和 `/projects` 角色项目页，不代表已接入新画布。旧单动作侧栏分为“抽帧 / 帧处理 / 导出”，整理与抠图没有强制先后关系。

- 抽帧：MP4 / MOV / WebM，选择时间范围和采样帧率；结果缩略图连续滚动，原尺寸播放使用弹窗。
- 整理：查看与勾选独立，批量删除勾选帧，悬浮垃圾桶删除单帧；拖动交换、撤销 / 恢复、循环候选。
- 抠图：当前全部保留帧，模型透明度＋局部 FFmpeg 去绿；双击打开精修弹窗，修改自动同步。**批量模型依赖独立单图项目，详见下文。**
- 导出：当前全部有序且已抠帧；原尺寸、比例尺寸、固定尺寸和自定义画布。裁剪与算法参数在高级设置中。
- PNG 序列＋JSON，或精灵图集 PNG＋JSON，统一 ZIP 下载。图集可查看整张排列；动作帧率明确写入说明文件，不覆盖源时间。
- 角色项目：从顶部“角色项目”进入独立工作区；项目素材与 `project.json` 保存在项目仓库，可在服务重启后重新打开。当前旧抠图结果可从“加入角色项目”迁入；跨动作尺寸与原点校准在R2完成。
- Godot 预览：完成角色校准后，打开随仓库提供的 `integrations/godot-preview` 工程并运行，再点项目工作区“Godot 预览”，把一次性地址和令牌填入Godot客户端。当前已在Godot 4.7.2 stable实测；只预览已保存的帧资产，编辑态变换/动作切换即时同步。令牌只在当前服务运行期间有效；预览不会改写角色项目或用户的Godot工程。正式导入功能尚未实现。
- JavaScript 适配：从角色工作区导出 ZIP 并解压，用 `/javascript-preview` 选择整个文件夹。示例会严格校验 v2 清单和 PNG 引用，播放固定帧率/逐帧时长动作并显示事件；适配器不请求服务端、不写输入包，也不是具体游戏引擎插件。

当前不是安装包。`/projects` 中已保存的角色项目可以跨刷新与服务重启恢复；旧 `/` 单动作临时工作区仍不会跨重启恢复，重新抽帧会清旧历史，未迁入项目的结果仍应及时下载或迁移。仅本机处理，不上传素材。

## 安装与启动

基础环境：Windows、Python 3.12、Node.js、Chrome，以及 PATH 中的 FFmpeg / ffprobe。当前本机 FFmpeg 验收版本为 8.1.1，未随仓库分发。Godot 只用于可选的原生预览；当前实测Godot 4.7.2 stable，不作为运行动作工坊网页端的依赖。Python依赖中的 `websockets` 为Uvicorn提供WebSocket传输实现；若移除此依赖，本机预览配对会被拒绝。

```powershell
git clone https://github.com/mhdfy1988/action-forge.git
Set-Location action-forge
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd ci
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8897 --no-access-log
```

用 Chrome 打开 http://127.0.0.1:8897/workflow 。旧单动作验证入口是 `/`，角色项目验证入口是 `/projects`。保持原浏览器、原8897站点访问已有工程；端口或浏览器不同会进入不同站点存储，不代表原数据已删除。不监听公网，不占用独立抠图入口8896；自动回归使用8898及独立缓存，历史8899隔离验收入口也不能替代主入口。

环境变量：`FRAMES_CACHE` 指定临时任务缓存；`ACTION_FORGE_PROJECTS` 指定可恢复角色项目仓库；`FRAMES_FFMPEG` / `FRAMES_FFPROBE` 指定程序路径。未知非空目录不会被接管。本地标准目录为 `action-forge`，代码按自身位置解析，不依赖目录名字。

### 批量模型的可选依赖

公开仓库**不包含**独立私有项目 `game-art-matting` 的 Python 模型代码、环境和权重。基础抽帧/整理可独立运行；当前统一导出只接已抠透明结果，因此完整抠图/精修/导出链路需要具备该依赖，不能把缺少模型的克隆当成完整安装。

默认依赖位于同级 `../game-art-matting`，使用其 `.venv/Scripts/python.exe`；可以显式指定 `FRAMES_MATTING_ROOT` 和 `FRAMES_MODEL_PYTHON`。缺失会报错，不切换替代算法。模型 CPU 测试可用 `FRAMES_MATTING_CPU_ONLY=1`。

精修编辑器已构建产物随本项目提供；如需重建，需要上述单图项目的源码、npm 依赖，再执行 `node scripts/build-matting-editor.mjs`。不修改独立 8896 的构建产物。本机配套版本及依赖边界见 [安装与仓库边界](docs/repository-guide.md)。

## 边界与文档
